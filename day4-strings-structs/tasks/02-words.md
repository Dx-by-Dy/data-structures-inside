# Задача 2. Разбор строки на слова

*Средняя. Питоновский `split`, сделанный без единого `malloc`: слова не
копируются никуда, а разделители превращаются в нули.*

## Что написать

Программу `02-words.c`, которая читает строки до конца ввода и для каждой
печатает список слов.

```c
size_t split_words(char *line, char *words[], size_t max_words);
```

`split_words` разбивает строку **на месте**: записывает `'\0'` на место каждого
разделителя, складывает адреса начал слов в массив `words` и возвращает число
найденных слов. Новая память при этом не выделяется, буквы никуда не
копируются.

Разделителями считаются пробел, табуляция и перевод строки.

## Как устроен ввод

Строки читаются функцией `fgets` в буфер фиксированного размера:

```c
char line[4096];
while (fgets(line, sizeof line, stdin) != NULL) { ... }
```

`fgets` читает до перевода строки включительно и всегда завершает прочитанное
нулём. Если строка во входе длиннее буфера, в него попадёт только начало — этот
случай надо обнаружить и сказать о нём.

## Пример запуска

```
$ printf 'the quick brown fox\n   спасибо   за   внимание  \n\n' | ./02-words
строка 1: слов 4
  1. "the" (3)
  2. "quick" (5)
  3. "brown" (5)
  4. "fox" (3)
  самое длинное: "quick"
строка 2: слов 3
  1. "спасибо" (14)
  2. "за" (4)
  3. "внимание" (16)
  самое длинное: "внимание"
строка 3: слов 0
  слов нет

всего: строк 3, слов 7, байт в словах 50
```

Длина печатается в байтах — сравните её с `len` того же слова в питоне и
объясните расхождение. Строка из одних пробелов даёт ноль слов.

При равных длинах самым длинным считается первое из таких слов.

## Сначала на Python

```python
for line in ["the quick brown fox", "   спасибо   за   внимание  "]:
    words = line.split()
    print(len(words), max(words, key=len))
```

`split` без аргументов сам пропускает несколько пробелов подряд и не создаёт
пустых слов — ваша функция должна вести себя так же.

А теперь посмотрите, чего в этой строке не видно:

```python
import sys
line = "the quick brown fox"
words = line.split()
print(sum(sys.getsizeof(w) for w in words), sys.getsizeof(line))
```

`split` создал четыре новых объекта, каждый со своим заголовком. Ваша программа
не создаёт ни одного: слова остаются лежать внутри прочитанной строки.
Посчитайте по выводу, во сколько раз больше памяти занял питоновский результат,
и скажите, за что эти байты заплачены.

## Требования

- `malloc` в этой задаче не используется. Буфер строки и массив указателей —
  массивы фиксированного размера.
- Слова не копируются. `words[k]` указывает внутрь `line`, и это проверяется на
  защите: попросят напечатать `words[0] - line`.
- Несколько разделителей подряд, разделители в начале и в конце строки дают
  ровно те же слова, что и одиночный пробел.
- Число слов в строке ограничено размером массива. Что делать с лишними —
  решите сами, но программа не должна писать за границу массива.
- Строка, не поместившаяся в буфер, распознаётся и не приводит к ошибке.
- `<string.h>` здесь уже можно.
- Санитайзер молчит, собирается без предупреждений.

## Проверьте себя

Скелета в этой задаче нет намеренно: функция одна, а `main` с чтением строк —
половина работы. Краевые случаи собираются в один запуск:

```sh
for t in "" " " "one" "  leading" "trailing  " "a  b   c" "the quick brown fox"; do
  printf '── вход: [%s]\n' "$t"
  printf '%s\n' "$t" | ./02-words | head -3
done
```

Семь случаев: пустая строка, строка из одного пробела, одно слово, пробелы в
начале, пробелы в конце, несколько пробелов между словами и обычная строка.
Первые два обязаны дать «строк 1, слов 0».

Отдельно — по-настоящему пустой ввод, в котором нет даже перевода строки:

```sh
printf '' | ./02-words | tail -1
```

Здесь `fgets` не вызывается ни разу, и строк должно быть ноль.

Отдельно — длинный вход и строка без перевода строки на конце:

```sh
seq 1000 | tr '\n' ' ' | ./02-words | tail -2
printf 'без перевода строки' | ./02-words | tail -2
```

Во втором случае слов должно быть три, и сообщения о непоместившейся строке
быть не должно.

И проверка на переполнение буфера:

```sh
python3 -c "print('x ' * 5000)" | ./02-words | tail -2
```

Здесь слов больше, чем помещается в массив, а байт — больше, чем в буфере.
Санитайзер обязан молчать и на этом входе.

## Краевые случаи

**Пустая строка.** `fgets` вернёт строку из одного символа `'\n'`. Слов ноль,
`words` не заполняется, печатать «самое длинное» нечего.

**Строка без слов.** Пробелы, табуляции и перевод строки — весь цикл проходит
по разделителям и не находит ни одного начала.

**Последняя строка без `'\n'`.** `fgets` вернёт её без завершающего перевода
строки. Отличить этот случай от переполнения буфера можно только по числу
прочитанных байтов.

## Что посмотреть после того, как заработает

**Где лежат слова.** Напечатайте для каждого слова `words[k] - line` — смещение
от начала буфера. Сравните с позициями слов в исходной строке.

**Что осталось от строки.** После разбора напечатайте первые 40 байт `line`
через `%d`, как в демонстрации 02. Найдите нули, которые поставила ваша
функция.

**Обратная операция.** Напишите функцию, которая склеивает слова обратно через
один пробел, и сравните результат с исходной строкой. Совпадёт не всегда —
скажите, в каких случаях.

**Сортировка слов.** Отсортируйте массив `words` по алфавиту, меняя местами
указатели, а не буквы, и напечатайте результат. Это заготовка к задаче 4.

## Подсказки

- Идиома разбора: пропустить разделители, запомнить адрес, пройти до
  следующего разделителя, записать туда `'\0'`.
- Записывать `'\0'` в место разделителя можно сразу, как только он найден: до
  начала следующего слова он уже не понадобится.
- Убедитесь, что `strlen(words[k])` даёт верную длину и для **последнего**
  слова в строке. Почему она вообще работает на словах внутри чужого буфера —
  вопрос на защиту.
- Перевод строки, оставленный `fgets`, — тоже разделитель. Проверьте на
  примере, что будет с последним словом строки, если про него забыть.
- Чтобы обнаружить непоместившуюся строку, хватит двух величин: длины
  прочитанного и того, чем оно кончается.

## Зачем это здесь

Так устроен `split` без выделения памяти — то, чем заняты быстрые разборщики
текста.
Заодно здесь видно, чего стоит ноль на конце: одна запись превращает середину
чужого массива в самостоятельную строку, и ни одна функция после этого не
догадается, что строка не своя.
