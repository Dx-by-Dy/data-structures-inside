# Задача 4. Записи

*Главная задача дня. Массив структур в куче, у каждой записи — своя строка в
куче, и на каждую из них ровно один владелец. Плюс отчёт о том, во что всё это
обошлось по байтам.*

## Что написать

Программу `04-records.c` с двумя структурами и шестью функциями:

```c
struct Person {
    char  *name;    /* строка в куче; владелец — эта запись */
    int    age;
    double score;
};

struct Db {
    struct Person *items;   /* блок в куче или NULL */
    size_t         len;     /* сколько записей занято */
    size_t         cap;     /* сколько помещается без переезда */
};

char     *my_strdup  (const char *s);
void      db_init    (struct Db *db);
void      db_free    (struct Db *db);
bool      db_reserve (struct Db *db, size_t need);
bool      db_push    (struct Db *db, const char *name, int age, double score);
long long db_find    (const struct Db *db, const char *name);
void      db_sort    (struct Db *db, int key);
```

`db_push` копирует имя в кучу. Почему копию нельзя заменить сохранённым
указателем — посмотрите в `main`, откуда имя приходит.

`db_find` возвращает номер записи с таким именем либо −1.

`db_sort` сортирует по ключу: 0 — по имени, 1 — по возрасту, 2 — по баллу. При
равных ключах порядок записей сохраняется.

Печать таблицы, разбор ввода и отчёт о памяти выданы готовыми.

## Как устроен ввод

Каждая строка — одна запись: имя без пробелов, возраст, балл.

```
Anna 17 4.5
Boris 18 3.9
```

Ключ сортировки задаётся аргументом командной строки: `name`, `age` или
`score`. Без аргумента берётся `name`.

## Пример запуска

```
$ printf 'Anna 17 4.5\nBoris 18 3.9\nVera 17 5.0\n' | ./04-records age
прочитано записей: 3
  Anna        17   4.50
  Boris       18   3.90
  Vera        17   5.00

отсортировано по возрасту:
  Anna        17   4.50
  Vera        17   5.00
  Boris       18   3.90

поиск "Boris": запись 2
поиск "Xenia": -1

память:
  sizeof(struct Person) = 24, сумма полей 20, дыр 4
  смещения: name 0, age 8, score 16
  массив: записей 3 при вместимости 4 = 96 байт
  строки: 16 байт в 3 блоках
  блоков в куче всего: 4
```

Anna и Vera обе семнадцатилетние, и после сортировки по возрасту Anna осталась
раньше Vera — так же, как они шли во вводе.

## Сначала на Python

```python
people = []
for line in ["Anna 17 4.5", "Boris 18 3.9", "Vera 17 5.0"]:
    name, age, score = line.split()
    people.append({"name": name, "age": int(age), "score": float(score)})

people.sort(key=lambda p: p["age"])
print([p["name"] for p in people])
```

Сортировка в Python устойчива: записи с одинаковым возрастом остаются в прежнем
порядке. Ваша `db_sort` обязана вести себя так же — проверьте на этом же
примере.

Теперь посмотрите, во что это обошлось:

```python
import sys
p = people[0]
print(sys.getsizeof(p), sum(sys.getsizeof(v) for v in p.values()))
```

Одна запись в Python — словарь с тремя ключами, и каждый из трёх объектов
внутри со своим заголовком. Сравните сумму с числом из строки
`sizeof(struct Person)` в отчёте вашей программы.

## Требования

- Имя копируется в кучу при добавлении. Хранить указатель на буфер, из
  которого читали, нельзя.
- У каждой строки ровно один владелец — запись, в которой она лежит. `db_free`
  освобождает **все** строки и массив, ровно по одному разу каждый.
- Порядок освобождения: сначала строки, потом массив. Что покажет санитайзер
  при обратном порядке — проверьте опытом из раздела ниже.
- `db_reserve` — единственное место, где вызывается `realloc`. Результат
  кладётся во временную переменную.
- `db_push` при нехватке памяти оставляет базу корректной и ничего не теряет.
  Обратите внимание: неудачей может кончиться и `db_reserve`, и `my_strdup`.
- `db_sort` меняет местами целые записи, а не содержимое строк. Строки при
  сортировке не копируются и не выделяются заново.
- Сортировка устойчива.
- После `db_free` структура описывает корректную пустую базу, и повторный
  вызов ничего не ломает.
- Санитайзер молчит, утечек нет, собирается без предупреждений.

## Проверьте себя

```sh
./04-records --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось:

```sh
./04-records --check && echo "база сошлась"
```

Тридцать одна проверка шестью блоками.

**Пустая база.** Состояние после `db_init`, поиск в пустой базе, сортировка
пустой базы.

**`my_strdup`.** Копия совпадает по тексту, лежит по другому адресу, и запись в
копию не задевает оригинал. Отдельно — копия пустой строки.

**Заполнение.** Три записи добавляются из **одного и того же** буфера: если имя
не скопировано, все три окажутся одинаковыми. Проверяется и то, что
`items[0].name` — не адрес этого буфера.

**Поиск.** Имя в середине, имя в начале, отсутствующее имя и имя в другом
регистре.

**Сортировка.** По каждому из трёх ключей подряд, с проверкой всего порядка
имён. Последняя из трёх — по возрасту при двух равных значениях: она проверяет
устойчивость.

**Рост на тысяче записей.** Длина, вместимость, имя последней записи и поиск
записи номер 500.

Отдельно проверьте руками пустой ввод: `printf '' | ./04-records` не должен ни
упасть, ни выдать отчёт санитайзера.

## Что посмотреть после того, как заработает

**Сколько блоков живёт одновременно.** В отчёте о памяти есть строка «блоков в
куче всего». Подайте на вход сто записей и сверьте это число с тем, что
показывает `LeakSanitizer`, если убрать один `free` в `db_free`.

**Порядок освобождения.** Поменяйте в `db_free` два цикла местами — сначала
`free(db->items)`, потом строки — и запустите. Прочитайте отчёт санитайзера и
скажите, чем эта ошибка отличается от утечки.

**Порядок полей.** Переставьте поля структуры: `double`, `char *`, `int`.
Посмотрите на новые смещения и на число дыр. Потом попробуйте `int`, `char *`,
`double` и объясните, почему размер вырос.

**Сортировка указателями.** Сделайте массив `struct Person *` и отсортируйте
его, не трогая сам массив записей. Сравните, сколько байт копирует каждый из
двух способов при одном обмене.

**Поиск по имени.** Замерьте время тысячи вызовов `db_find` на базе из тысячи
записей. Это O(n) на вызов; завтра ровно этот поиск будет стоить O(1).

## Подсказки

- Скопировать структуру целиком можно присваиванием: `db->items[j] =
  db->items[j - 1]`. Сколько байт при этом переносится и что происходит с
  буквами имени — посчитайте по полям структуры.
- Сортировка вставками получается устойчивой сама, если правильно выбрать
  строгость сравнения. Выбор придётся обосновать на защите.
- Имена сравниваются `strcmp`; почему не `==` — показывала демонстрация 10.
- В `db_push` порядок действий важен: если сначала увеличить `len`, а потом
  обнаружить, что `my_strdup` вернула `NULL`, в базе окажется запись с мусором
  в поле `name`.
- `db_find` возвращает `long long`, а не `size_t`, именно ради −1. Почему
  `size_t` здесь не годится, разбиралось в третьем дне.

## Зачем это здесь

Запись с именем — минимальная структура, у которой есть собственная память.
Всё, что вы сделаете завтра, устроено так же: хеш-таблица хранит пары
«ключ-строка — значение», владеет ключами и обязана освободить их ровно один
раз. Заодно отчёт о памяти показывает, где в вашей записи дыры, — и это первый
случай на курсе, когда порядок полей можно потрогать в собственном выводе.
