# Задача 5. Строка со счётчиком ссылок

*Со звёздочкой. Питоновский `str` целиком: заголовок и байты в одном блоке,
счётчик ссылок вместо `free`, хеш, который считается один раз. После неё
`sys.getsizeof` и `sys.getrefcount` cстанут понятнее.*

## Что написать

Программу `05-pystr.c` с объектом и пятью функциями:

```c
struct Str {
    size_t refcnt;   /* сколько имён ссылается на объект */
    size_t len;      /* длина в байтах, без завершающего нуля */
    long   hash;     /* -1, пока не посчитан */
    char   data[];   /* len + 1 байт следом за заголовком */
};

struct Str *str_new    (const char *text);
struct Str *str_incref (struct Str *s);
void        str_decref (struct Str *s);
struct Str *str_concat (const struct Str *a, const struct Str *b);
long        str_hash   (struct Str *s);
```

Последнее поле объявлено как массив неизвестной длины. Такое поле разрешено
только в конце структуры и места само не занимает: оно обозначает байты,
которые пойдут сразу за заголовком. Блок под объект выделяется одним вызовом:

```c
malloc(offsetof(struct Str, data) + len + 1)
```

`str_new` создаёт объект со счётчиком ссылок 1 и непосчитанным хешем.
`str_incref` добавляет ссылку, `str_decref` убирает; когда ссылок не осталось,
блок освобождается. `str_concat` создаёт новый объект, не трогая слагаемые.
`str_hash` считает хеш при первом обращении и запоминает его.

Плюс три счётчика — обычные переменные уровня файла: сколько объектов создано,
сколько освобождено и сколько раз хеш действительно считался.

## Как устроен ввод

Программа читает команды до конца ввода. Имена — одиночные буквы от `a` до `z`,
текст — слово без пробелов.

| Команда | Что делает                                                | Аналог в Python |
| -------------- | ------------------------------------------------------------------ | ---------------------- |
| `n a hello`  | создать объект и связать с именем`a` | `a = "hello"`        |
| `= b a`      | связать`b` с тем же объектом                | `b = a`              |
| `+ c a b`    | склеить и связать результат с`c`        | `c = a + b`          |
| `h a`        | напечатать хеш                                        | `hash(a)`            |
| `d a`        | отвязать имя                                            | `del a`              |
| `?`          | таблица имён                                            | —                     |
| `s`          | статистика                                               | —                     |

Присваивание имени, которое уже на что-то ссылалось, отпускает старый объект —
эта часть выдана готовой в функции `bind`.

## С чего начать

В каталоге лежит `05-pystr.c` — скелет с готовым разбором команд, таблицей
имён и печатью. Работы там пять мест, помеченных `TODO`.

Начинайте со `str_new`: пока она возвращает `NULL`, не работает ничего.

## Сначала на Python

```python
import sys
a = "hello"
b = a
print(a is b, sys.getrefcount(a))
print(sys.getsizeof(a), len(a))
```

`getrefcount` показывает то же число, что ваше поле `refcnt`, — только на
единицу больше: временная ссылка создаётся самим вызовом.

Дальше — то, ради чего задача существует:

```python
import ctypes
s = "".join(["hel", "lo"])          # не литерал, чтобы объект был свой
address = id(s)
print(ctypes.c_ssize_t.from_address(address + 16).value)   # длина
print(ctypes.c_ssize_t.from_address(address + 24).value)   # хеш
print(hash(s))
print(ctypes.c_ssize_t.from_address(address + 24).value)   # снова хеш
```

Первые 16 байт — счётчик ссылок и указатель на тип, дальше длина и хеш. До
вызова `hash(s)` в поле лежит −1, после — само значение. Ваша `str_hash`
устроена так же, и −1 там по той же причине.

## Требования

- Заголовок и байты — **один** блок. Отдельного `malloc` под текст быть не
  должно, и поле `data` не указатель.
- `str_new` кладёт в `hash` значение −1, а не 0. Почему именно −1 — вопрос на
  защиту; подумайте, какие значения хеш вообще может принимать.
- `str_hash` зависит от всех байтов строки, никогда не возвращает −1 и считает
  ровно один раз на объект. Алгоритм выбирайте любой.
- `str_concat` не меняет слагаемые и не трогает их счётчики. Счётчик ссылок
  результата равен 1, хеш — непосчитан.
- `str_decref(NULL)` законен и ничего не делает — как `free(NULL)`.
- Объект освобождается ровно тогда, когда счётчик дошёл до нуля, и ровно один
  раз.
- К концу работы освобождено столько же объектов, сколько создано. Санитайзер
  молчит.
- Собирается без предупреждений.

## Проверьте себя

```sh
./05-pystr --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось:

```sh
./05-pystr --check && echo "объект сошёлся"
```

Тридцать четыре проверки. Первой строкой печатается смещение поля `data` —
запомните это число, оно понадобится на защите.

**Создание.** Содержимое, длина, счётчик ссылок, непосчитанный хеш,
завершающий ноль. Отдельная проверка — что байты лежат ровно по смещению
`offsetof(struct Str, data)`: она отличает один блок от двух.

**Пустая строка.** Длина 0, объект существует, `data` — пустая строка.

**Ссылки.** `str_incref` возвращает тот же адрес, счётчик растёт и убывает, и
первый `decref` из двух объект не освобождает.

**Хеш.** Два вызова дают одно число, хеш не равен −1, считался ровно один раз,
сохранён в поле. Одинаковые строки дают одинаковый хеш, разные — разный.
Последняя проверка не сходится, если хеш смотрит не на все байты: строки в ней
различаются только последней буквой.

**Склейка.** Результат, его длина, его счётчик, непосчитанный хеш и то, что
слагаемое не изменилось ни содержимым, ни счётчиком.

**Освобождение.** Последний `decref` освобождает, `str_decref(NULL)` ничего не
делает, тысяча `incref` и тысяча `decref` возвращают счётчик на место, а в
конце создано и освобождено поровну.

## Что посмотреть после того, как заработает

**Цикл из ссылок.** Счётчик ссылок освобождает не всё. Придумайте
расположение объектов, при котором счётчик не дойдёт до нуля никогда, опишите
его словами и объясните, зачем в CPython, кроме счётчика, есть ещё сборщик
мусора. Это вопрос на защиту.

**Интернирование.** Добавьте таблицу из нескольких уже созданных строк и в
`str_new` возвращайте существующий объект, если такой текст уже есть, увеличив
его счётчик. Посмотрите, как изменится «создано объектов» на входе с
повторяющимися словами. Так Python обходится с литералами.

**Изменяемость.** Добавьте команду, которая меняет один байт строки на месте,
и посмотрите, что станет с сохранённым хешем. Объясните через это, почему
питоновский `str` неизменяем, а ключом словаря может быть только неизменяемый
объект.

**Сколько стоит заголовок.** Напечатайте `offsetof(struct Str, data) + len + 1`
для строк длины 1, 5 и 100 и сравните с `sys.getsizeof` для тех же строк в
Python. Разница постоянна — объясните, из чего она складывается.

## Подсказки

- `offsetof` живёт в `<stddef.h>`.
- Гибкий массив в конце структуры не занимает места: `sizeof(struct Str)` равен
  размеру заголовка, и просить у `malloc` надо `offsetof(...) + len + 1`.
- В `str_concat` длина результата — сумма длин, копировать удобно двумя
  `memcpy`, а завершающий ноль поставить руками.
- Простой хеш, которого достаточно: начать с большого числа, на каждом байте
  сделать «исключающее или» и умножить на другое большое число. Переполнение
  беззнакового типа здесь законно — про это был первый день.
- Если в конце «создано» и «освобождено» не сходятся, посмотрите на команду
  `=`: она обязана отпустить старый объект имени. В скелете это уже сделано —
  значит, дело в вашем `str_decref`.

## Зачем это здесь

Вторая половина вопроса дня, отвеченная своими руками: заголовок, длина, хеш и
счётчик ссылок — всё, из чего состоит питоновская строка. Завтрашний
