# Задача 5. Степень по модулю

*Со звёздочкой. Алгоритм вы знаете — а на C он сломается.*

## Что написать

Программу `05-powmod.c` с функцией

```c
uint64_t pow_mod(uint64_t base, uint64_t exp, uint64_t mod);
```

Быстрое возведение в степень по модулю.

```
$ printf '2 10 1000\n3 200 1000000007\n' | ./05-powmod
2^10 mod 1000 = 24
3^200 mod 1000000007 = 136318165
```

## В чём подвох

Обычный код бинарного возведения в степень содержит строку

```c
result = (result * base) % mod;
```

Пока `mod` маленький, всё хорошо. Возьмите `mod` близкий к 2⁶² — и произведение
двух чисел, каждое из которых меньше `mod`, **не поместится в 64 бита**.

Скажет ли вам об этом компилятор? А санитайзер? Ответьте до того, как
проверите, — и объясните свой ответ через демонстрацию
`../demo/02-unsigned-wrap.c`.

```sh
printf '3 100 4611686018427387847\n' | ./05-powmod
```

## Что нужно сделать

**1. Написать наивную версию и показать, что она врёт** на большом модуле.

Эталон у вас есть, и он встроен в Python: `pow(base, exp, mod)` считает ровно
то же самое и никогда не переполняется.

```sh
python3 -c "
import random
m = 4611686018427387847
for _ in range(20):
    b, e = random.randrange(m), random.randrange(1000)
    print(b, e, m, pow(b, e, m))
" > ref.txt
```

Прогоните первые три столбца через свою наивную версию и сравните с четвёртым.
Разойдётся почти на каждой строке.

Потом попробуйте `m = 1000000007` — и всё совпадёт. Объясните, почему граница
проходит именно там; это вопрос на защиту.

**2. Написать `mul_mod(a, b, mod)`** — умножение по модулю без переполнения.

Тот же приём двоичного разложения, что и в самом возведении в
степень, только для умножения — складываем и удваиваем по модулю. Переполниться
там может только сложение, а это лечится одной проверкой. Во что такое
умножение обходится по времени и как от этого меняется сложность всего
`pow_mod` — посчитайте сами, это вопрос на защиту.

Способ обходной: тип `__int128` — расширение gcc, не стандарт C. Пользоваться
им разрешено, но тогда на защите объясните, чем именно он помог и почему его
нет в стандарте.

## Проверьте себя

Скелета в этой задаче нет: функций всего две, а печатать надо одну строку.
Зато эталон есть встроенный — `pow(base, exp, mod)` в питоне.

Краевые случаи, которые надо прогнать, собраны в один вход:

```sh
printf '2 10 1000\n3 200 1000000007\n5 0 7\n0 0 7\n0 5 7\n7 3 1\n1 1000000 999999937\n2 62 4611686018427387847\n3 100 4611686018427387847\n' | ./05-powmod
```

И тот же вход через питон, чтобы было с чем сравнивать:

```sh
printf '2 10 1000\n3 200 1000000007\n5 0 7\n0 0 7\n0 5 7\n7 3 1\n1 1000000 999999937\n2 62 4611686018427387847\n3 100 4611686018427387847\n' | python3 -c "
import sys
for line in sys.stdin:
    b, e, m = map(int, line.split())
    print(f'{b}^{e} mod {m} = {pow(b, e, m)}')
"
```

Четыре случая из девяти стоит разобрать отдельно. `5 0 7` и `0 0 7` — нулевая
степень: скажите, что должно получиться во втором, и почему это не спор о
вкусах. `7 3 1` — модуль единица. Последние два — большой модуль, ради которого
задача и существует: наивная версия разойдётся с питоном именно на них.

## Требования

- Отдельная функция `mul_mod`, отдельная `pow_mod`.
- Собирается без предупреждений.
