# Задача 2. Три алгоритма, один ответ

*Здесь ваш алгоритмический курс встречается с моделью памяти, и они не совсем
сходятся.*

## Что написать

Программу `02-popcount.c`, которая считает количество единичных битов в
32-битном числе **тремя разными способами** и проверяет, что все три дали
одинаковый ответ.

1. **Наивный.** Цикл по всем 32 битам, проверка каждого. Всегда ровно 32
   итерации.
2. **Кернигана.** `v &= v - 1` в цикле убирает младший установленный бит.
   Итераций столько, сколько единиц.
3. **Табличный.** Заранее посчитайте ответ для всех 256 значений байта, потом
   разбирайте число на 4 байта и складывайте четыре значения из таблицы. Ровно 4
   обращения к памяти.

```
$ printf '0\n37\n-1\n255\n' | ./02-popcount
0           naive=0  kernighan=0  table=0   OK
37          naive=3  kernighan=3  table=3   OK
-1          naive=32 kernighan=32 table=32  OK
255         naive=8  kernighan=8  table=8   OK
```

Числа читаются до конца файла, по одному в строке. Если три ответа разошлись —
печатайте `MISMATCH` и завершайтесь с кодом 1.

## Сначала на Python

Все три способа сначала напишите на Python — там они занимают по три строки, и
видно, что это действительно три разных алгоритма, а не три записи одного.

```python
def naive(v):      return sum((v >> i) & 1 for i in range(32))
def kernighan(v):
    c = 0
    while v: v &= v - 1; c += 1
    return c
```

Проверьте, что оба совпадают со встроенным `bin(v).count('1')`.

Теперь посчитайте не ответ, а **число итераций** каждого способа для
`v = 1`, `v = 255`, `v = 2**31 - 1`. Выпишите три пары чисел на бумагу — они
понадобятся, когда будете отвечать, какой способ когда выигрывает.

И обратите внимание на то, чего в Python сделать не выйдет: `naive(v)` там
работает для любого `v`, включая `2**100`, и никакого «32» в нём быть не
должно. Откуда в вашей сишной версии взялось число 32 — вопрос на защиту.

## Требования

- Три отдельные функции: `popcount_naive`, `popcount_kernighan`,
  `popcount_table`. Все принимают `uint32_t`, возвращают `int`.
- Таблица на 256 элементов заполняется **в рантайме**, в начале `main`. Не
  вписывайте её в исходник числами.
- Собирается без предупреждений.

## Проверьте себя

```sh
./02-popcount --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось, поэтому проверку можно повесить в
конец сборки:

```sh
./02-popcount --check && echo "все три способа согласны"
```

Прогоняются десять чисел, по три проверки на каждое: ноль, единица, `-1`,
`255`, `256`, `65535`, `INT_MAX`, `INT_MIN`, `-256` и `2^30`. Тридцать
проверок.

Отдельно посмотрите на строку `INT_MIN`: там ровно одна единица, и это хорошая
проверка того, что вы нигде не потеряли старший бит.

## Подсказки

- Разберите на бумаге, что делает `v &= v - 1` для `v = 40` (это `101000`).

## Вопрос, ради которого задача существует

В алгоритмическом курсе все три функции — O(1). Выпишите для каждой, от
чего зависит число операций, и сформулируйте, что тогда означает эта запись,
если на практике способы различаются в разы. Это вопрос на защиту.

Прикиньте руками, без замеров: какой способ выиграет на числах, где почти все
биты нулевые, а какой — где почти все единичные. И назовите то, чем табличный
способ платит за свои четыре обращения.
