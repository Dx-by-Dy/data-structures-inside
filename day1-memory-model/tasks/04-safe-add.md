# Задача 4. Арифметика без UB

*Главная задача дня. Здесь очень легко написать код, который работает, и
который компилятор имеет полное право выбросить.*

## Что написать

Программу `04-safe-add.c` с тремя функциями:

```c
/* Кладут результат в *out и возвращают true, если он поместился в int.
   Если не поместился — возвращают false, а *out не трогают. */
bool safe_add(int a, int b, int *out);
bool safe_sub(int a, int b, int *out);
bool safe_mul(int a, int b, int *out);
```

Программа читает тройки вида `операция a b` и печатает результат или слово
`overflow`.

```
$ printf 'add 2 3\nadd 2147483647 1\nmul 100000 100000\nsub -2147483648 1\n' | ./04-safe-add
add 2 3 = 5
add 2147483647 1 = overflow
mul 100000 100000 = overflow
sub -2147483648 1 = overflow
```

## Сначала на Python — и здесь это неожиданно трудно

В Python переполнения нет, поэтому «безопасное сложение» там выглядит
бессмысленно. Тем интереснее написать его:

```python
INT_MIN, INT_MAX = -2**31, 2**31 - 1

def safe_add(a, b):
    r = a + b                      # никогда не переполнится
    return r if INT_MIN <= r <= INT_MAX else None
```

Обратите внимание, что произошло. Чтобы написать эту функцию, вам пришлось
**назвать границы явно** — Python сам их не знает. И проверку вы поставили
после сложения, потому что в Python это безопасно.

Ровно эти две вещи и переворачиваются в C: границы там знает компилятор, а
проверять после операции нельзя. Держите питоновскую версию открытой рядом —
она будет вашим эталоном ответов, пока вы воюете с С.

```sh
python3 -c "
INT_MIN, INT_MAX = -2**31, 2**31 - 1
import sys
for line in sys.stdin:
    op, a, b = line.split(); a, b = int(a), int(b)
    r = {'add': a+b, 'sub': a-b, 'mul': a*b}[op]
    print(op, a, b, '=', r if INT_MIN <= r <= INT_MAX else 'overflow')
" < tests.txt
```

## Главное требование

**Проверка происходит ДО операции, а не после.**

Вот решение, которое выглядит правильным и является полностью неверным:

```c
bool safe_add(int a, int b, int *out) {
    int r = a + b;            /* ← UB прямо здесь, до всякой проверки */
    if (a > 0 && b > 0 && r < 0) return false;
    ...
}
```

Переполнение здесь случается в первой строке, до всякой проверки. Чем это
заканчивается, показывала демонстрация `../demo/04-loop-never-ends.c`: с `-O0`
код работает, с `-O2` перестаёт.

Проверьте на себе:

```sh
gcc -std=c11 -O0 04-safe-add.c -o bad0 && printf 'add 2147483647 1\n' | ./bad0
gcc -std=c11 -O2 04-safe-add.c -o bad2 && printf 'add 2147483647 1\n' | ./bad2
```

Разошлись ответы — значит вы написали именно эту ошибку.

## Как надо

Переформулируйте условие переполнения так, чтобы в нём **не выполнялась**
опасная операция. Само условие выведите сами, это и есть содержание задачи.

Начните с вопроса: если `b` зафиксировано и положительно, при каком наибольшем
`a` сумма ещё помещается в `int`? Ответ на него сразу даёт проверку, которую
можно поставить до сложения. Потом разберите `b` отрицательное.

Отдельно убедитесь, что выражения в вашем условии сами не переполняются. Это
часть задачи, и на защите потребуется доказательство.

Для умножения условие длиннее: разберите случаи по знакам `a` и `b`, отдельно
обработайте `a == 0` и `b == 0`, и отдельно `-1` (это тот же `INT_MIN`, что в
задаче 3).

## Требования

- `#include <stdbool.h>` для `bool`.
- Нигде в коде не выполняется `a + b`, `a - b`, `a * b` до того, как проверка
  их разрешила.
- Собирается без предупреждений и **даёт одинаковый вывод при `-O0` и `-O2`**.
  Почему это работает как признак отсутствия UB — вопрос на защиту.
- На корректном решении `-fsanitize=undefined` молчит на любых входах. Он уже
  включён в `make`.

## Проверьте себя

```sh
./04-safe-add --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось, поэтому проверку можно повесить в
конец сборки:

```sh
./04-safe-add --check && echo "арифметика сошлась"
```

Прогоняются двадцать шесть случаев: по обычному на каждую операцию, все
границы и отдельная проверка того, что при отказе `*out` остаётся нетронутым.

Вот на что смотреть отдельно.

`add INT_MIN INT_MAX` и `mul 46340 46340` должны пройти, а `add INT_MAX 1` и
`mul 46341 46341` — нет. Если ваша программа заворачивает первые два, проверка
слишком строгая.

`sub 0 INT_MIN` — переполнение, хотя вычитается ноль. Объясните почему.

`mul INT_MIN 0` и `mul 0 INT_MIN` должны дать ноль, а не `overflow`: ноль
помещается в `int` при любом втором сомножителе.

`mul INT_MIN -1` и `mul -1 INT_MIN` — тот же краевой случай, что в задаче 3, и
проверить надо оба порядка аргументов.

И главная проверка дня — на двух уровнях оптимизации:

```sh
gcc -std=c11 -Wall -Wextra -O0 04-safe-add.c -o o0 && ./o0 --check > a.txt
gcc -std=c11 -Wall -Wextra -O2 04-safe-add.c -o o2 && ./o2 --check > b.txt
diff a.txt b.txt && echo "UB нет"
```

## Чем нельзя пользоваться

Встроенными функциями gcc `__builtin_add_overflow` и подобными.
На защите про них рассказать можно и нужно — если знаете, что они делают внутри.
