*Вы всю жизнь пользовались `//` и `%`. Оказывается, в C это не они.*

## Что написать

Программу `03-pydiv.c` с двумя функциями:

```c
int floor_div(int a, int b);   /* то же, что a // b в Python */
int floor_mod(int a, int b);   /* то же, что a %  b в Python */
```

Программа читает пары чисел до конца файла и печатает для каждой оба варианта —
сишный и питоновский.

```
$ printf '7 2\n-7 2\n7 -2\n-7 -2\n' | ./03-pydiv
7 / 2:  C -> 3 1   Python -> 3 1
-7 / 2:  C -> -3 -1   Python -> -4 1
7 / -2:  C -> -3 1   Python -> -4 -1
-7 / -2:  C -> 3 -1   Python -> 3 -1
```

## Python здесь — эталон

Вам не нужно гадать, что должно получиться: `//` и `%` в Python и есть
правильный ответ по определению задачи. Сгенерируйте эталонную таблицу
до того, как напишете хоть строчку на C:

```sh
python3 -c "
for a in range(-10, 11):
    for b in (-3, -2, -1, 1, 2, 3):
        print(a, b, a // b, a % b)
" > ref.txt
```

Теперь задача превращается в проверяемую: заставьте свою программу печатать в
том же формате и сравните.

```sh
cut -d' ' -f1,2 ref.txt | ./03-pydiv --pairs > mine.txt
diff ref.txt mine.txt && echo "совпало на всех парах"
```

Режим `--pairs` для этого уже есть в скелете: он печатает `a b a//b a%b` по
строке на пару, ровно в формате `ref.txt`. Основной вывод при этом остаётся
человекочитаемым, как в примере выше.

Обратите внимание, чего в `ref.txt` нет: пар с `b == 0`. Питон на них
возбуждает `ZeroDivisionError`, эталона для них не существует, и решать, что
делает в этом случае ваша программа, придётся отдельно.

## Требования

- `floor_mod(a, b)` при `b > 0` **всегда** возвращает неотрицательное число.
  Это ваше главное обещание, и проверяться будет именно оно.
- Ни при каких входных данных, кроме `b == 0`, в ваших функциях не должно быть
  UB.
- Собирается без предупреждений.

## Проверьте себя

```sh
./03-pydiv --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось, поэтому проверку можно повесить в
конец сборки:

```sh
./03-pydiv --check && echo "деление сошлось с питоном"
```

Прогоняются двенадцать пар с известными ответами, четыре пары, которые делить
нельзя, и две сплошные проверки: что `floor_mod` при `b > 0` всегда попадает в
`[0, b)`, и что тождество `(a // b) * b + a % b == a` держится на всех парах от
`-50` до `50`.

Два случая ломают программу, если их не проверить, и оба разбирались на
лекции: `b == 0` и `a == INT_MIN, b == -1`. В скелете за них отвечает функция
`divisible` — прочитайте её и скажите, почему второе условие выглядит именно
так и что произошло бы без него.

Отдельно посмотрите на строку `-1 / 2`: оба языка дают на ней разные ответы.
Запомните её, она понадобится в последнем разделе этого условия.
