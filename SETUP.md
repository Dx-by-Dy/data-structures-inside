# Как подключиться к учебной машине

Прочитайте этот файл до первой пары. Он короткий, и всё, что в нём есть, вам
понадобится каждый день.

---

## Ставить ничего не нужно

Компилятор на ваш компьютер не ставится. Вместо этого вы подключаетесь к
учебной машине с Linux, где `gcc`, `make`, `gdb` и Python уже стоят, и работаете
там. Причина простая: половина курса держится на санитайзерах — они показывают
выход за границу массива и переполнение, — а под Windows их нормально не
получить.

От вашего компьютера нужен только `ssh`. В Windows 10 и 11 он встроен: откройте
**PowerShell** или **Терминал** и наберите `ssh`. Если увидели список ключей и
описание — всё на месте. На macOS и Linux `ssh` есть всегда, работайте из
обычного терминала.

Тем, у кого стоит VS Code, подойдёт и он — как это настроить, написано ниже, в
разделе «Вариант с VS Code». Начать всё равно стоит с обычного подключения:
пароль и адрес там те же, а разбираться с одной незнакомой вещью проще, чем с
двумя сразу.

## Первое подключение

Преподаватель выдаст вам имя пользователя вида `student03` и пароль. Дальше:

```sh
ssh -p 2222 studentXX@147.45.103.146
```

`-p 2222` — номер порта, его нужно писать каждый раз.

В первый раз `ssh` спросит примерно так:

```
The authenticity of host '[147.45.103.146]:2222' can't be established.
ED25519 key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Это нормально: он видит машину впервые и просит подтвердить, что вы её
узнаёте. Наберите `yes` и нажмите Enter. Больше он этого не спросит.

Потом он попросит пароль:

```
studentXX@147.45.103.146's password:
```

**Пароль не отображается при вводе — ни звёздочками, ни точками.** Кажется,
будто ничего не набирается; на самом деле набирается. Введите его до конца и
нажмите Enter. Удобнее всего вставить пароль из буфера правой кнопкой мыши.

Если всё получилось, вы увидите приветствие курса и приглашение вида
`studentXX@...:~$`. Вы внутри.

Выйти обратно — команда `exit` или Ctrl+D.

## Что там лежит

Материалы курса — в каталоге `course` в вашем домашнем каталоге:

```sh
cd ~/course
ls
```

Это ваша личная копия: правьте в ней что угодно. Когда преподаватель выложит
новый день, он появится здесь сам. **Ваши файлы `.c` при этом не
перезаписываются** — решения останутся вашими, даже если условие задачи
обновится.

Домашний каталог виден только вам. Другие ученики в него заглянуть не могут.

Всё, что вы оставите на машине, сохраняется между входами. Отдельно ничего
сохранять не надо.

---

## Как решать задачи

Так же, как описано в [README.md](README.md), только каталог начинается с
`~/course`:

```sh
cd ~/course/day1-memory-model/tasks
make            # соберёт каждый .c в каталоге в отдельную программу
./01-binary     # запустить
make clean
```

Python там тоже есть, и он понадобится почти в каждой задаче: условия просят
сначала написать то же самое на знакомом языке, а потом сравнить с C. Свой
питоновский вариант складывайте рядом, в тот же каталог, и запускайте так:

```sh
python3 01-binary.py
```

## Чем править файлы

На машине стоят два редактора, оба запускаются из терминала.

**`nano`** — простой, начните с него:

```sh
nano 01-binary.c
```

Внизу экрана подсказки, где `^` означает Ctrl. Сохранить — Ctrl+O и Enter,
выйти — Ctrl+X.

**`vi`** — если вы уже знаете, как из него выйти.

## Вариант с VS Code

Если у вас уже стоит VS Code, можно работать в нём: он умеет открывать папку на
удалённой машине и редактировать файлы прямо там. Терминал внутри VS Code при
этом тоже удалённый, так что `make` и запуск программ никуда не переезжают.

Порядок такой.

1. Поставьте расширение **Remote — SSH** (в поиске расширений наберите
   `Remote - SSH`, издатель Microsoft).
2. Нажмите F1, начните набирать `Remote-SSH: Connect to Host` и выберите эту
   команду.
3. Выберите `+ Add New SSH Host` и введите строку целиком:

   ```
   ssh -p 2222 studentXX@147.45.103.146
   ```

   Куда сохранить настройку, он спросит следующим шагом — согласитесь с тем,
   что предложено по умолчанию.
4. Подключитесь к добавленному хосту. VS Code спросит пароль — тот же, что и
   для обычного входа. Тип платформы, если спросит, — **Linux**.
5. Когда откроется новое окно, выберите **Open Folder** и укажите
   `/home/studentXX/course` (со своим именем пользователя).

Терминал внутри VS Code открывается по Ctrl+\` — это тот же shell на учебной
машине, в нём работают и `make`, и `./01-binary`, и `man`.

**Первое подключение долгое.** VS Code скачивает на учебную машину свою
серверную часть — около 700 МБ в ваш домашний каталог. Это происходит один раз,
дальше подключение быстрое.

**Ограничение.** Память на учебной машине общая на всю группу, а VS Code
расходует её заметно больше, чем терминал: около 50 МБ на каждый запущенный
редактор, не считая того, что займёт открытый проект.

Это проверялось на самой машине. Десять редакторов, работающих одновременно,
она держит — даже когда вся группа в этот же момент запускает `make`.

Отсюда простое правило: вариант рабочий, но `nano` в терминале надёжнее. Если
VS Code отвалился, дело почти наверняка в памяти, переподключитесь
или доработайте занятие в терминале. Несохранённое при этом теряется, так что
сохраняйтесь почаще.

## Работать у себя, собирать на машине

Если хотите писать в привычном редакторе у себя, а собирать на машине,
копируйте файлы командой `scp` (запускать её нужно **у себя**, не внутри
подключения):

```sh
# отправить файл на машину
scp -P 2222 01-binary.c studentXX@147.45.103.146:~/course/day1-memory-model/tasks/

# забрать файл к себе
scp -P 2222 studentXX@147.45.103.146:~/course/day1-memory-model/tasks/01-binary.c .
```

Здесь `-P` заглавная, в отличие от `ssh`.

## Полезное

**Смените пароль на свой**, когда войдёте в первый раз:

```sh
passwd
```

Он спросит текущий пароль, потом новый дважды. Ввод, как обычно, не виден.

**Если связь оборвётся,** запущенная программа умрёт вместе с сессией. Когда
это мешает — например, вы запустили что-то долгое, — работайте в `tmux`:
наберите `tmux`, и сессия переживёт обрыв. Вернуться в неё после повторного
входа: `tmux attach`.

**Справка по любой функции** — командой `man`:

```sh
man printf
man 3 malloc
```

Выход из `man` — клавиша `q`.

## Если не подключается

**`Connection timed out` или `Connection refused`.** Скорее всего, сеть, из
которой вы выходите, не пропускает порт 2222 — так бывает в школьных и
корпоративных сетях. Проверьте с телефонного интернета: если оттуда работает,
дело в фильтре сети, скажите преподавателю.

**`Permission denied, please try again`.** Пароль не подошёл. Убедитесь, что
раскладка латинская, Caps Lock выключен, и что вы не потеряли символ при
переписывании: в пароле есть дефисы, они тоже часть пароля. После трёх попыток
`ssh` отключится — просто запустите команду заново.

**`Host key verification failed`.** Такое возможно, если машину пересобирали.
Скажите преподавателю, сами ничего не удаляйте.

## Что на машине делать нельзя

Ограничения там мягкие, но они есть, и лучше знать о них заранее.

Прав администратора у вас нет, `sudo` на машине не установлен. Ставить пакеты
не получится; всё, что нужно курсу, уже стоит.

Одному пользователю разрешено 96 процессов и файл не больше 256 МБ. В обычной
работе вы этого не заметите. Если увидите `fork: Resource temporarily unavailable`, значит,
программа наплодила процессов — почти наверняка это
ошибка в ней, а не тесность лимита.

Память общая на всю группу. Программа, которая выделяет память бесконечно,
будет остановлена системой; на других это не скажется, но своё несохранённое вы
потеряете. Сохраняйтесь перед запуском того, в чём не уверены.
