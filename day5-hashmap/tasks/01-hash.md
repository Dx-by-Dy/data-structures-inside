# Задача 1. Хеш-функции своими руками

*Разминка. Две хеш-функции по три строчки каждая, номер корзины и подсчёт
самой полной корзины — после этого станет видно, чем одна функция отличается
от другой.*

## Что написать

Программу `01-hash.c` с четырьмя функциями:

```c
uint32_t hash_sum(const char *s);
uint32_t hash_fnv1a(const char *s);
size_t   bucket_of(uint32_t hash, size_t cap);
size_t   longest_bucket(char words[][WORD_MAX], size_t count, size_t cap,
                        uint32_t (*hash)(const char *));
```

- `hash_sum` — сумма байтов строки. Байты берутся как `unsigned char`.
- `hash_fnv1a` — FNV-1a, 32 бита. Начальное значение 2166136261, множитель
  16777619; для каждого байта сначала исключающее ИЛИ, потом умножение.
- `bucket_of` — номер корзины для хеша. Число корзин `cap` — степень двойки, и
  деления в этой функции быть не должно.
- `longest_bucket` — сколько ключей окажется в самой полной корзине, если
  разложить `count` слов по `cap` корзинам функцией `hash`. Память под
  счётчики берётся в куче и освобождается здесь же.

Четвёртый аргумент `longest_bucket` — указатель на функцию: тип
`uint32_t (*)(const char *)` означает «адрес функции, которая принимает
`const char *` и возвращает `uint32_t`». Вызывается он как обычная функция:
`hash(words[i])`. Передаётся туда либо `hash_sum`, либо `hash_fnv1a` — имя
функции без скобок и есть её адрес.

## Как устроен ввод

Программа читает слова до конца ввода — по одному в строке или через пробел —
и для каждого печатает оба хеша и оба номера корзины. В конце печатаются две
гистограммы по шестнадцати корзинам.

## С чего начать

В каталоге лежит `01-hash.c` — скелет с готовым `main`, чтением слов и
печатью. Работы там четыре места, помеченных `TODO`.

Начинайте с `hash_sum`: она короче всех, и на ней проще всего убедиться, что
байты берутся правильно.

## Сначала на Python

```python
def hash_sum(s):
    return sum(s.encode())

print(hash_sum("abc"), hash_sum("bca"))
print(hash("abc"))           # встроенный хеш
print(hash("abc") % 16)      # номер корзины
```

Запустите `hash("abc")` дважды в одном интерпретаторе и ещё раз в новом.
Запишите, что получилось: на защите спросят, какое свойство хеш-функции при
этом сохраняется, а какое — нет.

Питоновский `hash` выдаёт числа со знаком и шириной 64 бита, ваш — без знака и
32 бита. Совпадения значений не ждите.

## Требования

- Байты строки берутся как `unsigned char`. В `--check` есть проверка, которая
  без этого не сходится; найдите её и объясните на защите.
- Умножение в `hash_fnv1a` переполняется почти на каждом шаге, и это
  ожидаемо. На защите спросят, чем такое переполнение отличается от
  переполнения `int` из первого дня.
- `bucket_of` не содержит `%` и `/`. Число корзин — степень двойки.
- `longest_bucket` выделяет память под счётчики в куче и освобождает её перед
  выходом. Санитайзер при завершении молчит.
- `longest_bucket` вызывается с `count`, равным нулю, — это законный вход.
- Сравнивать строки в этой задаче не нужно нигде.
- Собирается без предупреждений.

## Проверьте себя

```sh
./01-hash --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось:

```sh
./01-hash --check && echo "хеши сошлись"
```

Двадцать одна проверка четырьмя блоками.

**Сумма байтов.** Пустая строка, один символ, две анаграммы и строка из
русских букв. Последняя проверка ждёт 352.

**FNV-1a.** Шесть значений, посчитанных по описанию алгоритма: они одинаковы
на любой машине и в любом языке, поэтому их можно писать в условии.
`hash_fnv1a("")` равен 2166136261 — тому самому начальному значению.

**Номер корзины.** Четыре проверки, включая таблицу из одной корзины.

**Самая полная корзина.** Три анаграммы, разложенные по шестнадцати корзинам
двумя функциями, и вызов с пустым списком слов.

## Что посмотреть после того, как заработает

**Свой словарь.** Подайте на вход список слов побольше:

```sh
tr -c 'a-zA-Z' '\n' < /usr/share/common-licenses/GPL-3 | tr 'A-Z' 'a-z' | \
    grep -v '^$' | sort -u | head -200 | ./01-hash | tail -40
```

На двухстах английских словах разница между двумя функциями почти
исчезает — самая полная корзина выходит примерно одинаковой. Объясните, чем
этот набор ключей отличается от `key000 … key199` из демонстрации 3, и
придумайте двести ключей, на которых `hash_sum` проиграет.

**Другое число корзин.** Поменяйте `BUCKETS` на 8, потом на 64, и посмотрите,
как меняется самая полная корзина у каждой из функций.

**Третья функция.** Добавьте `hash_djb2`: начальное значение 5381, на каждом
шаге `h = h * 33 + байт`. Посмотрите, к какой из двух она ближе.

**Один изменённый байт.** Напечатайте `hash_fnv1a` для `hello` и `hellp`
в двоичном виде и посчитайте, сколько бит различается. То же самое сделайте
для `hash_sum`.

## Подсказки

- `uint32_t` — из `<stdint.h>`. Печатается как `%u`.
- Проход по строке байтами: `for (const unsigned char *p = (const unsigned char *)s; *p; p++)`.
- В `longest_bucket` под счётчики удобен `calloc`: он же их и обнуляет.
- Имя функции без скобок — её адрес: `longest_bucket(words, n, 16, hash_sum)`.

## Зачем это здесь

Хеш-функция — единственное, что стоит между ключом и номером корзины, и от неё
зависит всё остальное в этом дне. Две функции из этой задачи дальше
встретятся снова: одна в задачах 3–5, другая — в демонстрации 10.
