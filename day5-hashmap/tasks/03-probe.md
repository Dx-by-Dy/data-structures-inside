# Задача 3. Множество на открытой адресации

*Средняя. Таблица без единого `malloc`: ключ лежит прямо в слоте, а когда
слот занят — в следующем.*

## Что написать

Программу `03-probe.c` с пятью функциями:

```c
void   set_init    (struct Set *s);
size_t set_find    (const struct Set *s, const char *key, bool *found);
bool   set_add     (struct Set *s, const char *key);
bool   set_contains(const struct Set *s, const char *key);
bool   set_erase   (struct Set *s, const char *key);
```

Таблица фиксированного размера, шестнадцать слотов, и растёт она никогда:

```c
struct Set {
    char   keys[SET_CAP][WORD_MAX];
    int    state[SET_CAP];   /* SLOT_EMPTY, SLOT_USED или SLOT_DEAD */
    size_t live;             /* сколько ключей лежит */
    size_t dead;             /* сколько надгробий */
};
```

- `set_find` — главная функция задачи. Она возвращает номер слота и через
  `*found` сообщает, лежит ли ключ в таблице. Если ключ найден — это его слот;
  если нет — слот, в который его следует положить, либо `SET_CAP`, если
  положить некуда. Каждый просмотренный слот увеличивает `stat_probes`.
- `set_add` — добавить ключ; если он уже есть, не меняется ничего. `false`
  возвращается, только когда места нет.
- `set_erase` — удалить ключ; `false`, если его не было.

Хеш-функция `set_hash` дана готовой — это FNV-1a из задачи 1.

Остальные четыре функции устроены одинаково: они вызывают `set_find` и
разбирают её ответ.

## Как устроен ввод

Программа читает команды до конца ввода.

| Команда | Что делает                             | Аналог в Python |
| ------------- | ----------------------------------------------- | ---------------------- |
| `+ слово` | добавить                              | `s.add(w)`           |
| `? слово` | проверить, есть ли                | `w in s`             |
| `- слово` | удалить                                 | `s.discard(w)`       |
| `#`         | напечатать карту таблицы | —                     |
| `=`         | напечатать счётчики           | —                     |

## С чего начать

В каталоге лежит `03-probe.c` — скелет с готовой структурой, хеш-функцией,
разбором команд и печатью. Работы там пять мест, помеченных `TODO`.

Начинайте с `set_find`: пока она не работает, не работает ничего, а как только
заработает — остальные четыре функции пишутся по две-три строки каждая.

## Сначала на Python

В Python это встроенное множество:

```python
s = set()
s.add("red"); s.add("green"); s.add("blue")
s.discard("green")
print("blue" in s, len(s))
```

Разница, которую видно сразу: питоновское множество не покажет вам ни одного
слота. Ваша команда `#` показывает, и на защите по этой карте будут задавать
вопросы.

## Требования

- Поиск идёт от слота `set_hash(key) % SET_CAP` вперёд по кругу, по одному
  слоту.
- `SLOT_EMPTY` заканчивает поиск. `SLOT_DEAD` поиск не заканчивает, но годится
  для вставки.
- **Поиск обязан завершаться, даже если пустых слотов в таблице не осталось
  ни одного.** В `--check` есть отдельная проверка на это.
- Удаление оставляет `SLOT_DEAD` и увеличивает `dead`; вставка на место
  надгробия его уменьшает.
- Одинаковых ключей в таблице не бывает: `set_add` дважды подряд не меняет
  `live`.
- `malloc` в этой задаче не вызывается ни разу.
- `set_init` приводит в порядок структуру, каким бы ни было её прежнее
  содержимое.
- Санитайзер молчит, собирается без предупреждений.

## Проверьте себя

```sh
./03-probe --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось:

```sh
./03-probe --check && echo "множество сошлось"
```

Двадцать восемь проверок пятью блоками.

**Пустая таблица.** Поиск и удаление в ней, счётчики после `set_init`.
Структура перед вызовом заполняется мусором.

**Добавление.** Ключ, отсутствующий ключ и повторное добавление того же.

**Три ключа одной корзины.** Они подбираются перебором прямо в проверке,
поэтому зависят от вашей `set_hash` не больше, чем от её правильности. Средний
из трёх удаляется, после чего первый и третий обязаны находиться по-прежнему.
Затем удалённый ключ добавляется обратно — и число надгробий должно вернуться
к нулю.

**Полная таблица.** Шестнадцать ключей, семнадцатый, поиск отсутствующего
ключа в полной таблице и освобождение одного слота.

**Таблица из одних надгробий.** Шестнадцать ключей добавлены и все удалены.
Ни одного пустого слота в ней нет; поиск отсутствующего ключа обязан
завершиться, а вставка — сработать.

## Что посмотреть после того, как заработает

**Цена заполнения.** Заполните таблицу до пятнадцати ключей, печатая `=` после
каждого добавления. Выпишите, как растёт число просмотренных слотов, и
сравните с демонстрацией 08.

**Кластеры.** Подберите три-четыре слова с одной корзиной (перебором, как в
проверке) и посмотрите карту после их добавления. Потом добавьте слово,
корзина которого попадает в середину получившегося участка.

**Надгробия.** Добавьте и удалите один и тот же ключ пятнадцать раз, печатая
`=`. Объясните, что происходит со счётчиком `dead`, и скажите, когда таблица
перестанет принимать новые ключи.

**Другой шаг.** Замените переход к следующему слоту с `i + 1` на `i + 3` и
посмотрите на карту и счётчик проб. Потом попробуйте `i + 4` и объясните, что
изменилось.

## Подсказки

- Переход к следующему слоту по кругу: `i = (i + 1) % SET_CAP`.
- Цикл в `set_find` удобно писать по числу шагов: `for (size_t step = 0; step
  < SET_CAP; step++)`.
- Слот для вставки и слот, на котором остановился поиск, — разные вещи. Первое
  надгробие по дороге стоит запомнить.
- Копирование ключа в слот: `snprintf(s->keys[slot], WORD_MAX, "%s", key)`.
- `set_contains` — это `set_find` и одна проверка `found`.

Здесь появляются все три состояния слота и вся механика пробирования; в
задаче 4 к ним добавится только рост таблицы. Питоновские `set` и `dict`
устроены именно так, и надгробия в них называются `DKIX_DUMMY`.
