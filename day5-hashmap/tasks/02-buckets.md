# Задача 2. Корзины с цепочками

*Средняя. Таблица, в которой корзина — список: сюда складываются все ключи,
которым досталось одно и то же число.*

## Что написать

Программу `02-buckets.c`, которая раскладывает слова по корзинам, печатает
содержимое каждой корзины и считает, во что обходится поиск.

Корзина — односвязный список узлов:

```c
struct Node {
    char        *key;    /* копия слова в куче */
    struct Node *next;   /* следующий узел той же корзины или NULL */
};
```

Сама таблица — массив из `cap` указателей на узлы, выделенный в куче. Пустая
корзина — это `NULL`.

Скелета у этой задачи нет: `main`, чтение, печать и освобождение памяти —
половина работы, и делать её надо самому.

## Как устроен ввод

Первое число — число корзин, степень двойки от 1 до 1024. Дальше идут слова до
конца ввода, по одному в строке или через пробел. Слово не длиннее 31 байта.

Номер корзины считается так же, как в задаче 1: FNV-1a и маска по числу
корзин.

Слово, которое уже есть в таблице, второй раз не добавляется. Новый ключ
кладётся **в начало** своей цепочки, поэтому в печати слова одной корзины идут
в порядке, обратном порядку добавления.

## Пример запуска

```
$ printf '4 abc bca cab hello listen silent abc\n' | ./02-buckets
корзин 4
   0: silent
   1: cab bca
   2: listen
   3: hello abc
слов 7, разных 6
пустых корзин 0, самая длинная 2
поиск всех ключей: сравнений 8, в среднем 1.33
```

Строка «поиск всех ключей» получается так: каждый ключ, лежащий в таблице,
ищется в ней заново, и считается, сколько раз при этом вызвана `strcmp`.

## Сначала на Python

Та же таблица, только корзины — списки:

```python
def buckets(words, cap):
    table = [[] for _ in range(cap)]
    for w in words:
        b = hash(w) % cap
        if w not in table[b]:
            table[b].insert(0, w)
    return table

for i, b in enumerate(buckets("abc bca cab hello listen silent abc".split(), 4)):
    print(i, b)
```

Числа корзин у вас разойдутся: `hash` в питоне другой. Сравнивать надо не
номера, а длины цепочек и число сравнений.

Обратите внимание на строку `if w not in table[b]` — это ровно то место, где
ваша программа будет вызывать `strcmp`.

## Требования

- Таблица выделяется в куче под уже известное `cap`; узлы и копии слов — тоже
  в куче.
- Перед выходом освобождается всё: каждый ключ, каждый узел и сама таблица.
  Санитайзер при завершении молчит.
- Слово копируется в кучу целиком, вместе с завершающим нулём. Буфер, из
  которого оно пришло, переиспользуется на следующем слове.
- Одинаковые слова не порождают двух узлов.
- Число корзин, не равное степени двойки, и ноль — недопустимый ввод:
  напечатайте сообщение и завершитесь ненулевым кодом.
- Одна корзина (`cap` равен 1) — законный вход.
- Ввод без единого слова — законный вход.
- Собирается без предупреждений.

## Проверьте себя

Скелета здесь нет, поэтому проверка — запуском. Первые две команды должны
напечатать ровно то, что написано ниже.

```sh
printf '4 abc bca cab hello listen silent abc\n' | ./02-buckets | tail -3
```

```
слов 7, разных 6
пустых корзин 0, самая длинная 2
поиск всех ключей: сравнений 8, в среднем 1.33
```

```sh
printf '16\nabc bca cab hello listen silent abc\n' | ./02-buckets | tail -3
```

```
слов 7, разных 6
пустых корзин 11, самая длинная 2
поиск всех ключей: сравнений 7, в среднем 1.17
```

Краевые случаи проверяются так:

```sh
printf '1 a b c\n'  | ./02-buckets | tail -3    # одна корзина на три ключа
printf '4\n'        | ./02-buckets | tail -3    # ни одного слова
printf '3 a b\n'    | ./02-buckets; echo $?     # не степень двойки
printf '4 a a a a\n'| ./02-buckets | tail -3    # одно и то же слово четырежды
```

Последняя команда обязана напечатать «разных 1». Первая — «самая длинная 3» и
среднее число сравнений, которое вы можете посчитать на бумаге заранее.

И отдельно — под санитайзером, на большом входе:

```sh
tr -c 'a-zA-Z' '\n' < /usr/share/common-licenses/GPL-3 | tr 'A-Z' 'a-z' | \
    grep -v '^$' | (echo 256; cat) | ./02-buckets | tail -3
```

## Что посмотреть после того, как заработает

**Число корзин.** Прогоните один и тот же текст при `cap`, равном 16, 64, 256
и 1024, и выпишите среднее число сравнений. Постройте зависимость от
отношения «слов на корзину».

**Худший случай.** Подайте на вход только анаграммы одного слова и
посмотрите на таблицу. Потом замените в своей программе FNV-1a на сумму
байтов и посмотрите ещё раз.

**Порядок в цепочке.** Сделайте, чтобы новый ключ дописывался в конец цепочки,
а не в начало. Сравните число сравнений на том же входе и объясните, изменится
ли оно в среднем.

**Длина цепочки и время.** Замерьте `clock()` вокруг цикла поиска при `cap`,
равном 1024 и 8, на одном и том же тексте.

## Подсказки

- Массив корзин: `struct Node **buckets = calloc(cap, sizeof *buckets);` —
  `calloc` сразу кладёт во все корзины `NULL`.
- Вставка в начало списка — две строки: `n->next = buckets[b];` и
  `buckets[b] = n;`. Порядок этих двух строк важен.
- Освобождение цепочки: сохраните `next` **до** вызова `free`.
- Печать корзины и подсчёт её длины — один и тот же проход, если печатать и
  считать одновременно.
- `scanf("%zu", &cap)` читает `size_t`. Проверку «степень двойки» даёт одно
  выражение с побитовым И.

## Зачем это здесь

Цепочки — первый из двух способов разложить ключи, у которых совпали корзины;
второй разбирается в задаче 3. В этой задаче видно, из чего складывается
время поиска в таблице, и это то самое время, которое в Python называется
«O(1) в среднем».
