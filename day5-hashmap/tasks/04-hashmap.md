# Задача 4. Словарь

*Главная задача дня. К концу неё у вас в руках будет питоновский `dict`,
написанный целиком: хеш-таблица поверх вчерашнего динамического массива, с
ростом, удалением и порядком вставки.*

## Что написать

Файл `04-hashmap/hashmap.c`. Остальное в каталоге выдано готовым:


```sh

```

`make` здесь собирает **одну** программу из трёх файлов, а не три программы:
в `Makefile` для этого заданы `BIN` и `SRC`. Каждый `.c` компилируется
отдельно и ничего не знает про остальные — всё, что им нужно друг от друга,
написано в двух заголовках.

## Как устроен словарь

```c
struct Map {
    struct Vec entries;     /* записи в порядке вставки */
    int32_t   *index;       /* корзины: номера записей */
    size_t     index_cap;   /* сколько корзин; степень двойки */
    size_t     live;        /* сколько записей не удалено */
};
```

Два массива вместо одного. В корзине лежит не запись, а её номер в векторе:

- `MAP_EMPTY` (−1) — корзина никогда не была занята;
- `MAP_DEAD` (−2) — здесь был ключ, его удалили;
- любое неотрицательное число — номер записи в `entries`.

Запись — это ключ, его хеш и значение:

```c
struct Entry {
    char    *key;     /* копия ключа в куче; NULL — запись удалена */
    uint32_t hash;
    long     value;
};
```

Вектор `entries` заполняется только с конца и в порядке вставки. Поиск идёт по
корзинам, обход словаря — по вектору.

## Что писать

Шесть мест с `TODO` в `hashmap.c`:

| Функция | Что делает |
| ---------------- | ------------------------------------------------------------ |
| `map_hash`     | FNV-1a, 32 бита — тот же, что в задаче 1 |
| `map_init`     | пустой словарь                                      |
| `map_free`     | освободить ключи, вектор и корзины   |
| `find_slot`    | найти корзину ключа                          |
| `rehash`       | перестроить таблицу корзин                |
| `map_put`, `map_get`, `map_del`, `map_len` | операции словаря |

`find_slot` устроена так же, как `set_find` из задачи 3: возвращает номер
корзины и через `*found` сообщает, лежит ли ключ в словаре. Разница в том, что
в корзине лежит номер записи, а сам ключ — в векторе.

## Как устроен ввод

| Команда | Что делает | Аналог в Python |
| ------------------- | --------------------------------------------- | ---------------------- |
| `+ ключ значение` | положить или заменить        | `d[k] = v`           |
| `? ключ`          | напечатать значение              | `d[k]`               |
| `- ключ`          | удалить                                  | `del d[k]`           |
| `#`                 | напечатать словарь целиком | `print(d)`           |
| `=`                 | напечатать счётчики            | —                     |
| `* n`               | положить`n` ключей подряд     | цикл                 |

## Сначала на Python

```python
d = {}
d["one"] = 1; d["two"] = 2; d["three"] = 3
print(d)
d["two"] = 22
print(d)
del d["one"]
print(d)
d["one"] = 111
print(d)
```

Выпишите, в каком порядке печатается словарь в каждой из четырёх строк.
Особенно последнюю: ключ `one` там уже был и был удалён. Ваша программа должна
вести себя так же, и в `--check` есть проверка ровно на этот случай.

## Требования

- **Ключ принадлежит словарю.** `map_put` копирует ключ в кучу; буфер, из
  которого он пришёл, разрешено менять сразу после вызова.
- **Порядок вставки.** Новая запись дописывается в конец вектора. Замена
  значения у существующего ключа порядок не меняет.
- **Удаление.** Запись из вектора не вынимается: ключ освобождается, поле
  `key` становится `NULL`, в корзине остаётся `MAP_DEAD`.
- **Рост.** Занятых корзин, считая надгробия, всегда меньше трёх четвертей.
  Новый размер — наименьшая степень двойки, при которой живые записи занимают
  меньше трёх четвертей, но не меньше `INDEX_START`.
- **Перестройка уплотняет вектор.** Удалённые записи выбрасываются, порядок
  оставшихся сохраняется, надгробий после перестройки не остаётся.
- **Номер корзины** берётся маской, а не остатком.
- **`false` возвращается только при нехватке памяти**, и словарь после этого
  остаётся прежним и пригодным к работе.
- После `map_init` вектор пуст и корзин нет: память словарь просит при первой
  вставке.
- `map_free` освобождает всё и оставляет корректный пустой словарь; повторный
  вызов ничего не ломает.
- `vector.c`, `vector.h`, `hashmap.h` и `main.c` не меняются.
- Санитайзер молчит, утечек нет, собирается без предупреждений.

## Проверьте себя

```sh
./hashmap --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось:

```sh
./hashmap --check && echo "словарь сошёлся"
```

Сорок проверок семью блоками.

**Пустой словарь.** Структура заранее замусорена: `map_init` обязан привести
её в порядок, и это первая проверка. Пока она не сходится, остальные
пропускаются — дальше `main.c` читает поля структуры напрямую. `map_get`
отсутствующего ключа не трогает `*out`.

**Вставка, чтение, замена.** Три ключа, замена значения у одного из них и
порядок вставки, собранный в строку.

**Ключ принадлежит словарю.** Ключ кладётся из буфера, буфер после этого
затирается. Проверяется и то, что ключ читается по-прежнему, и то, что он
лежит по другому адресу.

**Удаление.** Порядок оставшихся ключей, повторное удаление и возвращение
удалённого ключа обратно.

**Три ключа одной корзины.** Подбираются перебором по вашей же `map_hash`.
Средний удаляется, первый и третий обязаны находиться.

**Рост.** Тысяча ключей, потом каждый второй удаляется, потом тысяча новых.
Проверяются степень двойки, заполненность меньше трёх четвертей, сохранность
порядка и то, что таблица не разрослась без причины.

**`map_free` дважды подряд.**

## Что посмотреть после того, как заработает

**Цена вставки.** Сравните два запуска:

```sh
printf '* 1000\n=\n'   | ./hashmap | tail -6
printf '* 100000\n=\n' | ./hashmap | tail -6
```

Поделите «просмотрено корзин» на число ключей в каждом запуске. Числа будут
близки; объясните, почему они не растут.

**Сравнений ключей.** В обоих запусках их окажется неправдоподобно мало.
Найдите в своём коде строку, которая за это отвечает.

**Порядок вставки на большом словаре.** Запустите `* 100000`, потом удалите
несколько ключей командой `-` и напечатайте `#`. Убедитесь, что порядок
оставшихся не изменился.

**Плохой хеш.** Замените `map_hash` на сумму байтов и запустите `* 100000`
снова. Сравните «просмотрено корзин» и время работы.

**Сжатие.** Сейчас таблица растёт, но не уменьшается. Сделайте так, чтобы при
удалении она перестраивалась, когда живых записей осталось меньше четверти, и
посмотрите, что изменится в счётчиках.

## Подсказки

- Начинайте с `map_hash` и `map_init`: пока они не работают, не работает
  ничего.
- `find_slot` пишется один раз и используется всеми тремя операциями. Если у
  вас получилось три похожих цикла, вернитесь к задаче 3.
- Номер корзины считается так же, как в `bucket_of` из задачи 1. Условие,
  при котором это верно, обеспечивает `rehash`.
- У записи есть поле `hash`. Порядок, в котором вы сравниваете хеш и строку,
  спросят на защите.
- `rehash` вызывается и когда корзин ещё нет вовсе: `index_cap` равен нулю.
  Отдельной ветки для этого не нужно, если размер считается циклом от
  `INDEX_START`.
- В `rehash` при раскладке записей по новым корзинам сравнивать ключи не с
  чем: в новой таблице их ещё нет.
- В `map_free` три вызова `free` на разные вещи. Прежде чем писать их
  подряд, посмотрите, откуда берутся адреса ключей.
- `map_put` может не получить память в двух разных местах. Оба нужно
  обработать так, чтобы словарь остался рабочим.
