# Задача 1. Массив, длину которого узнали во время работы

*Разминка. Вчера длину массива требовалось знать при компиляции. Сегодня она
приходит со входа, и память под массив просится у системы явно.*

## Что написать

Программу `01-alloc.c` с четырьмя функциями:

```c
int      *alloc_array(size_t n);                 /* выделить блок на n элементов */
bool      read_array(int *a, size_t n);          /* прочитать n чисел со входа */
long long sum(const int *a, size_t n);
int      *copy_array(const int *a, size_t n);    /* новый блок с теми же числами */
```

Программа читает длину, затем сами числа, печатает сумму, а потом показывает
разницу между копией и общим доступом.

```
$ printf '5\n10 20 30 40 50\n' | ./01-alloc
n = 5, запрошено байт: 20
элементы: 10 20 30 40 50
сумма = 150
sizeof a = 8 (это указатель, а не массив)

copy_array, затем copy[0] = 999:
  оригинал: 10 20 30 40 50
  копия:    999 20 30 40 50

int *alias = a, затем alias[4] = -1:
  оригинал: 10 20 30 40 -1
  алиас:    10 20 30 40 -1

освобождено два блока
```

Две последние пары строк — это вчерашний вопрос дня, заданный ещё раз. Обе
записи выглядят почти одинаково, а результат у них разный: скажите по выводу,
что именно делает каждая, и на защите это спросят снова.

## Сначала на Python

```python
n = int(input())
a = [0] * n
```

Строка `[0] * n` в Python пишется не задумываясь, а вчера на C её написать было
нечем: `int a[n]` с переменной `n` запрещён флагом `-Wvla`, а массив
фиксированного размера пришлось бы объявлять «с запасом». Сегодня появляется
`malloc`, и запись становится прямой.

Проверьте заодно, чего в Python не видно:

```python
import sys
n = 5
a = [0] * n
print(sys.getsizeof(a))       # 96
b = a[:]                      # копия
c = a                         # тот же список
b[0] = 999
c[1] = -1
print(a)                      # [0, -1, 0, 0, 0]
```

`a[:]` в Python и `copy_array` в вашей программе делают одно и то же, только
Python выделяет память сам. Кто выделил — тот и освобождает, и в C это придётся
написать руками.

## С чего начать

В каталоге лежит `01-alloc.c` — скелет с готовым `main` и четырьмя пустыми
функциями. Он собирается и запускается, ничего осмысленного пока не печатая.
Работы там четыре места, помеченные `TODO`; `main` менять не нужно.

## Требования

- Результат `malloc` проверяется на `NULL` **всегда**, сразу после вызова.
- Каждый выделенный блок освобождается ровно один раз. Санитайзер при
  завершении должен молчать — в том числе на ошибочных входах.
- Размер запрашивается записью `n * sizeof *a`, а не `n * sizeof(int)`.
- Печатает только `main`; функции ничего не печатают.
- Собирается без предупреждений.

## Краевые случаи

**`n == 0`.** Что вернёт `malloc(0)` — стандарт оставляет на усмотрение
библиотеки, и оба возможных ответа законны. Отсюда вопрос: как ваша программа
отличает «длина нулевая» от «памяти не хватило», если в обоих случаях можно
получить `NULL`? Напечатать на такой длине надо что-нибудь осмысленное:

```
$ printf '0\n' | ./01-alloc
n = 0, запрошено байт: 0
элементы:
сумма = 0
sizeof a = 8 (это указатель, а не массив)

массив пуст, показывать нечего
```

**Огромное `n`.** Произведение `n * sizeof *a` считается в `size_t`. Подберите
такое `n`, при котором это произведение переполнится, и скажите, какого размера
блок выделит `malloc` и чем закончится запись во второй элемент. Проверка нужна
**до** умножения.

**Нехватка памяти.** Ветку с `NULL` стоит проверить, и делать это надо сборкой
**без** санитайзера:

```sh
gcc -std=c11 -Wall -Wextra 01-alloc.c -o plain
printf '100000000000\n' | ./plain
```

`malloc` вернёт `NULL`, и программа должна сообщить об этом и завершиться. Под
санитайзером тот же запрос ведёт себя иначе: он не возвращает `NULL`, а
останавливает программу сообщением `AddressSanitizer: out of memory`. Это ещё
один случай, когда санитайзер меняет поведение, а не только наблюдает за ним.

## Проверьте себя

```sh
./01-alloc --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось:

```sh
./01-alloc --check && echo "выделение сошлось"
```

Главная проверка — `alloc_array при переполнении вернул NULL`. Пока её нет в
вашем коде, `alloc_array` выдаст блок на пару байт, и скелет об этом скажет.

Про `malloc(0)` скелет не проверяет ничего и печатает результат в скобках:
стандарт разрешает оба ответа, и требовать один из них было бы неверно.

Остальное — что `copy_array` действительно выделяет **другой** блок, что
запись в копию не видна в оригинале, а запись через алиас видна.

## Подсказки

- `size_t` — беззнаковый тип для размеров, вычитание из нуля в нём даёт
  огромное число. Читайте длину в знаковый тип, проверяйте на
  неотрицательность и только потом приводите к `size_t`.
- `SIZE_MAX` объявлен в `<stdint.h>`, `bool` — в `<stdbool.h>`.
- Печать размера через `%zu`, суммы через `%lld`.
- Освобождать оба блока нужно и на пути, где чтение не удалось. Проще всего
  сделать в `main` один выход с `free`, а не разбрасывать `free` по ветвям.

## Зачем это здесь

Это первая программа курса, в которой память просится и возвращается явно. Всё
остальное в этом дне — та же пара `malloc`/`free`, только блок при этом ещё и
меняет размер.
