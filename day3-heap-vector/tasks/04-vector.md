# Задача 4. Свой динамический массив

*Главная задача дня. К концу неё у вас в руках будет питоновский `list`,
написанный целиком: блок в куче, длина, вместимость и все операции, включая
амортизированный `append`.*

## Что написать

Программу `04-vector.c` со структурой и семью функциями:

```c
struct Vec {
    int    *data;   /* блок в куче или NULL */
    size_t  len;    /* сколько элементов занято */
    size_t  cap;    /* сколько помещается без переезда */
};

void vec_init   (struct Vec *v);
void vec_free   (struct Vec *v);
bool vec_reserve(struct Vec *v, size_t need);              /* обеспечить вместимость */
bool vec_push   (struct Vec *v, int value);                /* append */
bool vec_pop    (struct Vec *v, int *out);                 /* pop() */
bool vec_insert (struct Vec *v, size_t pos, int value);    /* insert(pos, value) */
bool vec_erase  (struct Vec *v, size_t pos);               /* pop(pos) */
```

К ним добавится `move_range` из вчерашней задачи 4 — восьмое место с `TODO`.
Печать вектора (`vec_print`) и разбор команд выданы готовыми.

Плюс три счётчика — обычные переменные уровня файла:

- сколько раз выделялся новый блок;
- сколько элементов при этом перенесено;
- сколько элементов сдвинуто при вставках и удалениях.

## Как устроен ввод

Программа читает команды до конца ввода. Команда — один символ, за которым
могут идти числа.

| Команда | Что делает                                    | Аналог в Python |
| -------------- | ------------------------------------------------------ | ---------------------- |
| `+ x`        | добавить`x` в конец                    | `a.append(x)`        |
| `-`          | снять последний                          | `a.pop()`            |
| `i p x`      | вставить`x` на позицию `p`        | `a.insert(p, x)`     |
| `d p`        | удалить элемент на позиции`p` | `a.pop(p)`           |
| `?`          | напечатать вектор                      | `print(a)`           |
| `* n`        | добавить`n` чисел подряд          | цикл с`append`  |
| `=`          | напечатать счётчики                  | —                     |

Команды читаются по одному символу: `scanf(" %c", &cmd)`, где пробел перед
`%c` пропускает пробелы и переводы строк. Строк в этой задаче нет намеренно —
они будут завтра.

## С чего начать

В каталоге лежит `04-vector.c` — скелет с готовой структурой, разбором команд,
печатью и счётчиками. Работы там восемь мест, помеченных `TODO`: `vec_init`,
`vec_free`, `vec_reserve`, `move_range` и четыре операции.

Начинайте с `vec_reserve`: пока она возвращает `false`, не работает ничего
остального, а как только заработает — заработает и `vec_push`.

## Сначала на Python

Проверьте, что ваш вектор ведёт себя как список:

```python
a = [1, 2, 3, 4, 5]
a.insert(0, 99); print(a)     # [99, 1, 2, 3, 4, 5]
a.pop(2);        print(a)     # [99, 1, 3, 4, 5]
a.pop();         print(a)     # [99, 1, 3, 4]
```

А потом посмотрите, чего в Python не видно. Счётчик переездов, который вы
напишете, там тоже есть — просто он спрятан:

```python
import sys
a = []
prev = sys.getsizeof(a)
moves = 0
for i in range(100000):
    a.append(i)
    now = sys.getsizeof(a)
    if now != prev:
        moves += 1
        prev = now
print(moves)
```

Сравните это число с тем, что печатает ваша программа на `* 100000`. Оба числа
малы, оба растут как логарифм длины, и различаются они только основанием
логарифма — то есть выбранным множителем роста.

## Требования

- `vec_reserve` — единственное место во всей программе, где вызывается
  `realloc`. `vec_push` и `vec_insert` обращаются к нему, а не растят блок
  сами.
- `vec_reserve(v, need)` обеспечивает вместимость **не меньше** `need`,
  удваивая текущую, пока её не хватает. Уже достаточной вместимости она не
  трогает и `realloc` при этом не вызывает.
- Результат `realloc` кладётся во временную переменную. При неудаче вектор
  остаётся прежним и **корректным**: можно продолжать им пользоваться.
- Сдвиг при вставке и удалении делается функцией `move_range` из вчерашней
  задачи 4. Возьмите её текст и перенесите сюда; направление копирования в ней
  выбирается само.
- После `vec_free` структура описывает корректный пустой вектор, и повторный
  вызов ничего не ломает.
- Каждая функция, кроме `vec_print`, ничего не печатает; печатает `main` и
  `vec_reserve` (журнал роста).
- Санитайзер молчит, утечек нет.
- Собирается без предупреждений.

## Проверьте себя

```sh
./04-vector --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось:

```sh
./04-vector --check && echo "вектор сошёлся"
```

Тридцать пять проверок пятью блоками.

**Пустой вектор.** `vec_pop` и `vec_erase(0)` обязаны вернуть `false` и не
трогать `*out`, `vec_insert(5, x)` — тоже `false`, а `vec_insert(0, 7)` должна
сработать: вставка в начало пустого списка законна.

**`vec_free` дважды подряд.** После второго вызова структура обязана описывать
корректный пустой вектор: `len 0`, `cap 0`, `data == NULL`.

**Рост.** Вместимость проверяется по шагам: 4 после первого `vec_push`, всё
ещё 4 при длине четыре, 8 при длине пять. Если у вас там другие числа,
удвоение начинается не в тот момент.

**Вставка и удаление в середине.** Проверяется всё содержимое вектора, а не
только длина, — сдвиг должен попадать точно.

**Амортизация на ста тысячах добавлений.** Ожидаются `cap 131072`, шестнадцать
переездов и 131068 перенесённых элементов. Все три числа выводятся из
стратегии удвоения, начатой с четвёрки: посчитайте их на бумаге, прежде чем
запускать.

Отдельно проверьте `* 0` руками: `printf '* 0\n=\n' | ./04-vector` не должен ни
добавить элемент, ни переехать.

## Что посмотреть после того, как заработает

**Амортизация не только на ста тысячах.** Возьмите миллион вместо ста тысяч:
`printf '* 1000000\n=\n' | ./04-vector`. Отношение «перенесено» к длине
останется меньше двух.

**Цена вставки в начало.** Сравните два запуска одинаковой длины:

```sh
printf '* 10000\n=\n' | ./04-vector | tail -4
python3 -c "print('i 0 1\n' * 10000 + '=')" | ./04-vector | tail -4
```

Десять тысяч добавлений в конец и десять тысяч вставок в начало. Счётчик сдвигов
во втором случае будет на несколько порядков больше, и второй запуск заметно
дольше первого. Так выглядит разница между `append` и `insert(0, x)`,
посчитанная в элементах.

Не берите здесь сто тысяч: время растёт как квадрат, и под санитайзером такой
запуск займёт около десяти секунд.

**Сжатие.** Python умеет уменьшать блок, когда занято меньше половины
вместимости. Добавьте это в `vec_erase` и посмотрите, как изменится вывод
`=` на длинной последовательности удалений.

## Подсказки

- `bool` — из `<stdbool.h>`. Возвращать `bool` из операций, которые могут не
  получиться, удобно: `if (!vec_push(&v, x)) { ... }` читается прямо.
- Поля структуры через указатель читаются стрелкой: `v->len` — то же, что
  `(*v).len`.
- `vec_reserve` на пустом векторе получает `v->data == NULL`, и
  `realloc(NULL, bytes)` в этом случае равносилен `malloc(bytes)`. Отдельной
  ветки не нужно.
- Аргументы `move_range` при вставке и удалении посчитайте на бумаге, как вчера.
  При удалении элемента `pos` сдвигается `len - pos - 1` элементов.
- Позицию читайте в знаковый тип и проверяйте на отрицательность до приведения
  к `size_t`: `-1` в `size_t` превращается в огромное число, и проверка
  `pos > v->len` его поймает, а `pos >= 0` — нет.
