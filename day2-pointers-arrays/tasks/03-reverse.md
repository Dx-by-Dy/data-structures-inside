# Задача 3. Обращение и циклический сдвиг

*Два указателя, идущие навстречу друг другу. И алгоритм, который делает
циклический сдвиг тремя обращениями и без единого лишнего байта памяти.*

## Что написать

Программу `03-reverse.c` с двумя функциями:

```c
void reverse(int *a, size_t n);                /* переворачивает массив на месте */
void rotate_left(int *a, size_t n, size_t k);  /* циклический сдвиг влево на k */
```

На входе: длина, потом сами числа, потом `k`.

```
$ printf '6\n1 2 3 4 5 6\n2\n' | ./03-reverse
исходный:   1 2 3 4 5 6
обращённый: 6 5 4 3 2 1
сдвиг влево на 2: 3 4 5 6 1 2
```

Массив после печати обращённого варианта возвращается в исходное состояние, и
сдвиг применяется к исходному. Как именно вернуть — решайте сами; способ,
который не требует второго массива, здесь очевиден.

`k` может быть больше длины:

```
$ printf '5\n1 2 3 4 5\n7\n' | ./03-reverse
исходный:   1 2 3 4 5
обращённый: 5 4 3 2 1
сдвиг влево на 7: 3 4 5 1 2
```

## Сначала на Python

Сделайте то же самое на Python и посмотрите, чем эти три строки отличаются друг
от друга:

```python
a = [1, 2, 3, 4, 5, 6]
b = a[::-1]
a.reverse()
c = a[2:] + a[:2]
```

Проверьте `id(a)` до и после `a.reverse()`, а потом `id(b)` и `id(a)`.

Скажите про каждую из трёх строк, создаёт она новый список или переставляет
элементы в старом, и как это видно по `id`.

**Ваши обе функции работают на месте.** Никаких вспомогательных массивов: до
третьего дня выделить второй массив нечем.

Отдельно посчитайте на Python, сколько элементов переставляет `a.reverse()` для
списка из шести элементов, и сколько раз при этом происходит обмен. Это число
понадобится на защите.

## Как делается сдвиг тремя обращениями

Циклический сдвиг влево на `k` — это три обращения подряд:

1. обратить первые `k` элементов;
2. обратить оставшиеся `n - k`;
3. обратить весь массив целиком.

Проверьте на бумаге для `1 2 3 4 5 6` и `k = 2`, прежде чем писать код. Три
строчки, и ни одного лишнего байта памяти.

Заметьте, что второй вызов начинается не с начала массива: ему передаётся
`a + k` и длина `n - k`. Почему это законный вызов — показывала демонстрация
`07-slice.c`.

## Требования

- `reverse` работает **через два указателя**, идущих навстречу, а не через
  индексы. Условие цикла — `left < right`.
- `rotate_left` вызывает `reverse` ровно три раза и ничего не копирует.
- Обе функции корректны при `n == 0`. Проверьте: пустой ввод не должен ни
  падать, ни печатать мусор.
- `k` приводится к диапазону одним `%`. Подумайте, что делать при `n == 0`,
  прежде чем писать `k %= n`.
- Собирается без предупреждений.

## Подсказки

- Обмен через временную переменную: `int t = *left; *left = *right; *right = t;`
- `left < right` для указателей — законное сравнение, пока оба показывают внутрь
  одного массива.
- `size_t` беззнаковый: посчитайте, чему равно `n - 1` при `n == 0`, и что
  из этого следует для `a + n - 1`. Явную проверку `n == 0` пишете вы, и на
  защите нужно будет показать, где она стоит.

## Проверьте себя

Скелета в этой задаче нет: функций две, и способ вернуть массив в исходное
состояние вы должны найти сами. Зато краевые случаи собираются в один вход:

```sh
for t in "0::0" "1:7:0" "1:7:1" "6:1 2 3 4 5 6:0" "6:1 2 3 4 5 6:6" "5:1 2 3 4 5:7"; do
  n=${t%%:*}; rest=${t#*:}; a=${rest%:*}; k=${rest##*:}
  echo "── n=$n k=$k ──"
  printf '%s\n%s\n%s\n' "$n" "$a" "$k" | ./03-reverse
done
```

Шесть случаев: пустой массив, один элемент со сдвигом на ноль и на единицу,
сдвиг на ноль, сдвиг на всю длину и `k` больше длины.

Первый и второй ломают программу, если `k %= n` написано до проверки `n == 0`.
Третий и четвёртый должны напечатать массив без изменений — если нет, значит
`reverse` вызывается не три раза или не с теми аргументами.

Ожидаемый результат каждого сдвига даёт питон: `a[k % n:] + a[:k % n]`.
