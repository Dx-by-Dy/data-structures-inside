# Задача 4. Сдвиг с перекрытием

*Главная задача дня. Копирование участка массива в тот же массив: направление
цикла здесь решает всё, и выбрать его надо не наугад.*

## Что написать

Программу `04-shift.c` с пятью функциями:

```c
void copy_forward(int *dst, const int *src, size_t n);   /* цикл от начала к концу */
void copy_backward(int *dst, const int *src, size_t n);  /* цикл от конца к началу */
void move_range(int *dst, const int *src, size_t n);     /* корректно всегда */

size_t delete_at(int *a, size_t n, size_t pos);
size_t insert_at(int *a, size_t n, size_t cap, size_t pos, int value);
```

Первые три копируют `n` элементов из `src` в `dst`. Различаются только
порядком, в котором они это делают. Пока участки не пересекаются, все три дают
одно и то же; вся задача про то, что происходит, когда пересекаются.

Последние две реализуются **через** `move_range` и возвращают новую длину
массива. Это питоновские `list.pop(pos)` и `list.insert(pos, value)`, только
руками.

## Что такое сдвиг на k

Сдвигается не весь массив, а его участок, и длина массива при этом не меняется.

**Сдвиг вправо на `k`.** Элементы с индексами `0 … n-k-1` переезжают на места
`k … n-1`. Первые `k` элементов не меняются, последние `k` прежних значений
затираются.

```
индекс: 0 1 2 3 4 5 6 7
было:   1 2 3 4 5 6 7 8
стало:  1 2 1 2 3 4 5 6   на местах 2..7 лежат бывшие элементы 0..5
        ^^^ места 0..1 не тронуты
```

Приёмник выше источника: `dst = a + k`, `src = a`, переносится `n - k`
элементов.

**Сдвиг влево на `k`.** Элементы с индексами `k … n-1` переезжают на места
`0 … n-k-1`. Последние `k` элементов не меняются.

```
индекс: 0 1 2 3 4 5 6 7
было:   1 2 3 4 5 6 7 8
стало:  3 4 5 6 7 8 7 8   на местах 0..5 лежат бывшие элементы 2..7
                    ^^^ места 6..7 не тронуты
```

Приёмник ниже источника: `dst = a`, `src = a + k`, переносится `n - k`
элементов.

Шесть строк вывода — это шесть вызовов с этими аргументами:

| Строка вывода | Вызов |
| --- | --- |
| вправо, `copy_forward`  | `copy_forward(a + k, a, n - k)`  |
| вправо, `copy_backward` | `copy_backward(a + k, a, n - k)` |
| вправо, `move_range`    | `move_range(a + k, a, n - k)`    |
| влево, `copy_forward`   | `copy_forward(a, a + k, n - k)`  |
| влево, `copy_backward`  | `copy_backward(a, a + k, n - k)` |
| влево, `move_range`     | `move_range(a, a + k, n - k)`    |

Печатается каждый раз **весь** массив из `n` элементов, включая нетронутый
хвост: по нему видно, что сдвиг задел ровно то, что должен был.

## Формат ввода и пример запуска

Три строки: длина, сами элементы, затем четыре числа.

```
8                 длина массива n (не больше вместимости вашего массива)
1 2 3 4 5 6 7 8   элементы
2 3 1 99          k, позиция удаления, позиция вставки, вставляемое значение
```

Здесь `k = 2` (на столько сдвигаем в обе стороны), `3` — индекс элемента,
который удаляется, `1` и `99` — куда и что вставляется. Значение `k` лежит в
пределах от `0` до `n`.

```
$ printf '8\n1 2 3 4 5 6 7 8\n2 3 1 99\n' | ./04-shift
исходный:         1 2 3 4 5 6 7 8

сдвиг вправо на 2 (dst выше src):
  copy_forward:   1 2 1 2 1 2 1 2
  copy_backward:  1 2 1 2 3 4 5 6
  move_range:     1 2 1 2 3 4 5 6

сдвиг влево на 2 (dst ниже src):
  copy_forward:   3 4 5 6 7 8 7 8
  copy_backward:  7 8 7 8 7 8 7 8
  move_range:     3 4 5 6 7 8 7 8

через move_range делаются pop и insert:
  delete_at(3):      1 2 3 5 6 7 8
  insert_at(1, 99):  1 99 2 3 5 6 7 8
```

Перед каждым из шести опытов рабочий массив восстанавливается из нетронутой
копии — иначе сравнивать будет нечего. Последние две строки идут подряд по
одному массиву: `insert_at` применяется к тому, что осталось после `delete_at`,
поэтому в предпоследней строке семь элементов, а в последней снова восемь.

Посмотрите на четыре строки с испорченными данными и найдите закономерность:
испорченный результат — это не мусор, в нём отчётливо видно, что произошло.

## Сначала на Python

Тот же сдвиг вправо на два:

```python
a = [1, 2, 3, 4, 5, 6, 7, 8]
a[2:] = a[:-2]
print(a)          # [1, 2, 1, 2, 3, 4, 5, 6]
```

Никаких проблем с перекрытием, хотя участки пересекаются самым наглым образом.
Скажите, что именно стоит справа от знака равенства и во что это обходится для
списка из миллиона элементов.

В C такой копии никто не сделает. У вас есть один массив, и вы пишете в него,
одновременно из него читая. Значит, порядок обхода становится частью
алгоритма.

Проверьте и `pop` с `insert`:

```python
a = [1, 2, 3, 4, 5, 6, 7, 8]
a.pop(3); print(a)
a.insert(1, 99); print(a)
```

Внутри CPython обе операции — это именно сдвиг участка массива указателей.
Посчитайте, сколько элементов сдвигает `insert(0, x)` в списке из миллиона и
сколько — `append`, и скажите, какая из двух операций дороже и во сколько раз.
На третьем дне вы напишете обе сами.

## Как рассуждать

Пусть `dst` и `src` показывают в один массив и участки пересекаются.

Возьмите сдвиг вправо на 2 из примера: `dst = a + 2`, `src = a`, `n = 6`.
Выпишите на бумаге первые три присваивания цикла `copy_forward` и найдите
момент, когда программа читает ячейку, в которую сама же и записала минуту
назад. Дальше всё разваливается предсказуемо, что и видно по выводу.

Теперь то же самое для `copy_backward` на том же сдвиге — испорченного чтения
не будет. А для сдвига влево всё наоборот.

Отсюда правило для `move_range` формулируется одной строкой: **направление
копирования выбирается по взаимному расположению `dst` и `src`**. Какое куда —
выведите сами; в этом состоит основная работа.

Код возврата не ноль, если что-то разошлось:

```sh

```

Двадцать четыре проверки. Обратите внимание: **испорченные результаты здесь
такие же ожидаемые, как правильные**. `copy_forward` на сдвиге вправо обязан
дать `1 2 1 2 1 2 1 2`, а `copy_backward` на сдвиге влево — `7 8 7 8 7 8 7 8`.
Если у вас получилось что-то другое, направление цикла не то, каким объявлено.

Смотреть отдельно надо на четыре вещи.

При `k == 0` и при `k == n` массив обязан остаться прежним.

В проверке `n == 0` три вызова с нулевой длиной делаются по массиву `111 222`.
После них должно остаться `111 222`. Если числа поехали, посмотрите, от чего
считает ваш обратный цикл.

`insert_at` при заполненном массиве обязана вернуть прежнюю длину, а не
испортить память за границей.

`insert_at` с `pos == n` — законная операция, это добавление в конец.

## Требования

- `memcpy`, `memmove` и любые другие функции из `<string.h>` использовать
  **нельзя**: вы пишете `memmove` сами. На четвёртом дне ваше решение можно
  будет сравнить с библиотечным.
- `move_range` содержит ровно одно сравнение указателей и два вызова.
- `delete_at` и `insert_at` не копируют ничего сами: они вызывают `move_range`
  с правильными аргументами. Продумайте эти аргументы на бумаге.
- `insert_at` возвращает прежнюю длину, если места больше нет (`n == cap`) или
  позиция за пределами массива.
- Собирается без предупреждений, санитайзер молчит на всех примерах.

## Краевые случаи

Проверьте до сдачи:

- `n == 0` в любой из трёх копирующих функций — цикл не должен выполниться ни
  разу. Обратите особое внимание на `copy_backward`: посчитайте, чему равно
  `n - 1` в типе `size_t` при `n == 0`, и что из этого следует для цикла.
- `delete_at` последнего элемента: сколько элементов двигает `move_range`?
- `insert_at` в конец, то есть `pos == n`: это законная операция, и она должна
  работать.
- `k == 0`: сдвиг на ноль не должен ничего испортить.
- `k == n`: переносить нечего, все шесть строк должны совпасть с исходным
  массивом.

## Подсказки

- Идиома обратного цикла по `size_t`, в которой нет вычитания из нуля:
  `for (size_t i = n; i-- > 0; )`. Разберите её: условие проверяется до
  уменьшения, тело выполняется после.
- Сравнение `dst < src` для указателей внутри одного массива — законно.
- Хранить нетронутую копию исходного массива придётся отдельным массивом той же
  длины: перед каждым опытом восстанавливайте рабочий.
- Проверять себя удобно питоном: любой ваш результат сравнивается со срезами.
