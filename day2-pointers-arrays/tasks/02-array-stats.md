# Задача 2. Массив и его длина

*Про то, чего в C у массива нет: длины.*

## Что написать

Программу `02-array-stats.c`, которая читает числа до конца ввода (не больше
ста), складывает их в массив и печатает статистику.

```
$ printf '3 -1 4 -1 5 -1\n' | ./02-array-stats
прочитано чисел: 6
сумма    = 9
среднее  = 1.500
минимум  = -1 (совпадений: 3)
максимум = 5 (совпадений: 1)
```

Пустой ввод — тоже правильный ввод:

```
$ printf '' | ./02-array-stats
прочитано чисел: 0
массив пуст, считать нечего
```

Функции, из которых состоит решение:

```c
long long sum(const int *a, size_t n);
int minimum(const int *a, size_t n);
int maximum(const int *a, size_t n);
size_t count_equal(const int *a, size_t n, int value);
```

## Сначала на Python

Тот же вывод на Python пишется в четыре строки:

```python
a = [3, -1, 4, -1, 5, -1]
print(len(a), sum(a), min(a), max(a), a.count(min(a)))
```

Теперь посмотрите на этот код внимательно и ответьте на два вопроса.

Первый: откуда `len(a)` знает длину — считает её или читает готовую? И почему
в C так не получится. Ответ был на лекции, а демонстрация `08-decay.c`
показывала, во что превращается `sizeof` внутри функции.

Второй: что вернёт `sum` на большом списке? Попробуйте:

```python
print(sum([2_000_000_000] * 3))
```

Ваша сишная версия обязана дать то же число. Тип результата выбирайте,
посчитав заранее, какая сумма вообще возможна на ста элементах.

## С чего начать

В каталоге лежит `02-array-stats.c` — скелет с готовым `main`, чтением ввода и
печатью. Работы там четыре места, помеченные `TODO`.

## Требования

- Все четыре функции принимают `const int *` и `size_t`. Никаких глобальных
  переменных: длина передаётся аргументом, всегда.
- `const` не для красоты: функция, которая только читает, обязана это объявить.
  Попробуйте написать `a[0] = 0` внутри `sum` — компилятор не предупредит, а
  откажется собирать программу. Прочитайте текст ошибки целиком.
- `sum` возвращает `long long`. На защите нужно объяснить, почему не `int`, и
  назвать вход, на котором `int` дал бы неверный ответ.
- `minimum` и `maximum` вызываются только при `n > 0`. Проверку делает `main`,
  а не они.
- Среднее печатается с тремя знаками после запятой. Делить надо на `(double)n`,
  и объяснить, почему без приведения ответ был бы другим.
- Собирается без предупреждений.

## Подсказки

- Читать до конца ввода с ограничением: `while (n < CAP && scanf("%d", &v) == 1)`.
- `size_t` — беззнаковый тип, которым в C измеряют размеры. Печатается как
  `%zu`. Циклы по массиву пишите с ним, а не с `int`.
- В `count_equal` попробуйте обойти массив без индекса, через указатель:
  `for (const int *it = a; it != a + n; it++)`. Это та же запись, что вы видели
  в демонстрации `06-array-bounds.c`.
- Сравнивать `double` на равенство не нужно — среднее просто печатается.

## Проверьте себя

```sh
./02-array-stats --check
```

Он сам сравнивает то, что вернули ваши функции, с правильными ответами и
печатает `ok` или `ОШИБКА` на каждую проверку, а в конце — «сошлось N из M».
Код возврата не ноль, если что-то разошлось, поэтому проверку можно повесить в
конец сборки:

```sh
./02-array-stats --check && echo "статистика сошлась"
```

Прогоняются пустой массив, один элемент, четыре одинаковых, сумма больше
`INT_MAX`, границы `int` и пример из условия — двадцать одна проверка.

Строка `sum трёх по 2000000000` — та, ради которой `sum` возвращает
`long long`. Посчитайте ожидаемое число на бумаге и сверьте с тем, что
напечатано.

В строке с границами `int` лежат `INT_MAX`, `INT_MIN` и ноль. Скажите заранее,
чему равна сумма, и объясните знак результата.

Отдельный опыт, который стоит поставить руками: уберите из `report` проверку
`n == 0` и вызовите `minimum` на пустом массиве. Предскажите до запуска, что
напечатается, чем закончится программа и скажет ли что-нибудь санитайзер, — а
потом проверьте. Последнее из трёх спрашивают на защите.
